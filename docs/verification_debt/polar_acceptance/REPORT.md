# 极地验收判据的判别力审计：criterion (b) 无判别力、(e) 通过反向控制

**任务**：mission 1855（tp-ver-3 verifier 席自主工时，model 钉扎 deepseek-v4-flash）
**分支**：`agent/m1855` · **EDIT_WHITELIST**：`docs/`, `tests/`（船舶生产代码不在本仓改）
**被审对象**：`backend/services/polar/{channel,optimizer}.py` 的两个**自验收端点**
`GET /polar/acceptance/channel`（criterion b）与 `GET /polar/acceptance/route`（criterion e）。
两者在 `docs/audit/ship_api_evidence_ledger.json` 里均为 `evidence=UNCOVERED`
（44 个船舶端点中 14 个 UNCOVERED，本次清 2 个）。

**一句话结论**：判据 (e) 是真判据（三个反向控制全部判红）；判据 (b) 不是——
它的 hold-out 相对误差可解析地化简为**纯混合物密度比** $\rho_b(c)/\rho_b(c_a)-1$，
对生产模型全部物理参数（浓度堆积指数、速度动力因子、摩擦系数、B/T/L）**零判别力**：
8 个把绝对阻力改动 −43 %～+76 % 的变异**全部存活**（8/8 PASS）。

## ① 案例介绍（物理背景 / 几何 / 参数）

**物理背景.** 船在破冰船尾随航道（brash ice channel）中航行时，阻力 =
敞水阻力 + 碎冰（brash）项。某战役节点（W3-N11）要求「Riska/VTT 型航道公式，
标定后通过浓度 hold-out 检验」，模块把该要求实现成一个**自验收端点**：

* 生产式 `R_brash(c) = ρ_b(c)·g·h_b·(B·T·Cb)·(μ_b + sinβ)·(c/c_max)^n·(1 + C_VEL·v/√(g h_b))`
* 参考式 `R_ref(c) = k·ρ_i·g·h_b²·B·(c/c_max)^n·(1 + C_VEL·v/√(g h_b))`
* `k` 只在锚点 `c_a = 0.40` 上拟合；`c = 0.20, 0.70` 为 hold-out；
  判据：`max|相对误差| ≤ 10 %` 即 PASS。

**算例船与工况**（全部取自模块预设，未手改）

| 参数 | 值 |
|---|---|
| 船 | `handysize_bulker`（polar 模块预设，L=180 m 级、B、T、Cb 由 `get_ship` 读取） |
| 航速 | 6.0 kn（`v_kn`） |
| brash 层厚 | `h_b = 0.80 m` |
| 浓度扫描 | 0.10, 0.20, 0.30, 0.40, 0.50, 0.60, 0.70 |
| 锚点 / hold-out | 0.40 / {0.20, 0.70} |
| 密度 | ρ_i、ρ_w 取自 `services.polar.constants` |

**判据 (e) 的算例**：`nsr_corridor` 合成冰场、`DEFAULT_ROUTE_SHIP`、deadline 30 h、
起点/终点取模块默认；基线族 16 条经验航线（直航、6 条纬度带 dogleg、lead-aware 引航，
各配 2 种速度策略）。

## ② 怎么做的（方法 / 流程 / 关键设置 / 工具链）

1. **扫描定位**（全只读）：`docs/audit/ship_api_evidence_ledger.json` 的 44 个船舶端点中
   14 个 `WITHHELD/UNCOVERED`；近 20 条报告已覆盖阻力/推进/耐波/操纵/稳性/振噪/绿色航行/VV-GCI
   的验证欠账，**极地自验收端点**无人复核 → 选它，避免重复。
2. **解析推导（先证后测）**：把 `k` 的标定代回参考式，得到 `R_ref(c) = A(c_a)·P(c)·D`，
   于是判据里的相对误差 = `A(c)/A(c_a) − 1 = ρ_b(c)/ρ_b(c_a) − 1`。该式**不含** n、C_VEL、μ_b、
   B、T、h —— 判据的全部信息内容就是「密度混合物律」。
3. **变异电池（mutation battery）**：不改仓库代码，运行时 `setattr` 扰动
   `C_PACKING_EXP`（×1.3/×0.7）、`C_VEL`（×2）、`MU_BRASH`（×1.5）、`C_MAX_PACKING`（×0.85），
   并用 `dataclasses.replace` 扰动船宽/吃水/船长；每例同时记录「判据结论」与「物理结果漂移」。
   漂移在**变异上下文内部**取值（首版在上下文外取值导致漂移恒为 0，已修正——这是本单最实在的一个坑）。
4. **反向控制**：把 `optimizer.plan_voyage` 临时替换成「最佳经验航线本身」（saving≈0）、
   「只省 3 %」与「正好 5.0 %」三种输出，检查判据是否必须判红。
5. **工具链**：`docs/verification_debt/polar_acceptance/discriminate.py`（复跑一次 ≈ 50 s，
   含一次 23 s 的航线优化）→ `artifacts/discrimination.json` + 3 张图；
   回归 `tests/test_polar_acceptance_discrimination.py`（**14 passed, 4 xfailed(strict)**，离线可复跑）。

## ⑤ 注意点（坑 / 局限 / 适用范围）

1. **坑（本单踩到并修）**：变异电池首版把「物理漂移」放在 `setattr` 恢复之后取值，
   漂移恒为 0（看起来「变异没生效」）。必须在变异上下文内部采样，否则审计会把
   「判据无判别力」误判成「变异无效」。
2. **结论的适用范围**：本审只针对**判据本身**（verification 的「软件/判据质量」层面），
   不评判 brash 阻力模型的物理精度。模型对实船 brash 阻力的绝对精度仍然
   **WITHHELD**（无公开标定试验数据在本仓可回读；与 level-ice 的 m1720 结论同级）。
3. **判据 (b) 的修法（派给 ship-performance-platform，本仓不得改船舶代码）**：
   ① 参考式的 `P(c)`/速度因子不能再与生产式共用同一函数（否则在比值里被约掉）；
   ② 或改成绝对量比对：对独立来源的 brash 阻力（拖曳试验/VTT 数据）比对绝对值而非比值；
   ③ 判据必须至少能拒绝 M1–M5 中一项，否则不称「hold-out 检验」。
   本单已用 4 条 `xfail(strict=True)` 钉住现状：一旦参考式改成真正独立，strict 会立刻转红提醒更新判据。
4. **判据 (e) 的残余风险**：`pass` 依赖单一合成冰场与单一船型；本单只做了控制类检验
   （能否判红），未做跨冰场/跨船型的稳健性扫描（时间预算内为轻量任务，且 load15≈123 > 100，
   按容量纪律未起重算力）。

## ⑥ 误差判定（逐项，显式回答「是否 <3%」）

| 关键量 | 基准 / 判据 | 实测 | 是否 <3% |
|---|---|---|---|
| 解析律 vs 判据实测相对误差 | 闭式 ρ_b(c)/ρ_b(c_a)−1（恒等式） | 最大偏差 **8.33e-17** | **是**（<1e-14） |
| 判据 (b) 名义 max 相对误差 | 10 % 阈值 | 2.9358 % | **是** |
| 判据变异存活率 | 期望 0（应判红） | **1.00（8/8）** | **否** ← 本单核心发现 |
| 名义优化节能 vs 最佳经验航线 | 5 % 阈值 | 9.009 % | **是**（超阈值 4.0 pp） |
| N1/N2/N3 控制节能 | 必须 <5 % | 0.000 / 3.000 / 5.000 % | **是**（全部判红） |
| 等 ETA 口径差 | deadline 30 h | +0.003 h（0.01 %） | **是** |

**是否全部 <3%：除「变异存活率」（本条按判据口径衡量，实测 1.00，属 FAIL）外，其余全部 <3%。**
该 FAIL 不是本单工具的问题，而是**被审判据 (b) 判别力为零**的实测结论，如实登记、未粉饰。
