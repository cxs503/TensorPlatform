## 1. 建设目标（不变，进度见 §6）

Tensor 的目标不是把若干求解器简单拼接，而是让 Agent 在权限、资源预算、验证规则和人工审批边界内组织研究循环：从目标解析、实验计划、求解器执行，到证据审查、结果归档和下一轮决策。

成功标准：自主性 / 可执行 / 可验证 / 可追溯 / 可复现 / 可扩展 / 科学可信（定义同 V1.0 §1）。

## 3. 现有工程基础盘点（V1.1 刷新）

### 研发管线（V1.0 未预见，现为体系主干）

- **v7 三站制**：worker（干活+本机自测绿+commit）→ pusher（纯传输，推完即开 PR，零裁决）→ merge_master（唯一裁决者）。
- **本机裁决 doctrine**（owner 2026-11-06：「GitHub 只是代码的托管，本机确认能跑直接合并」）：对每张 agent PR 在 99 共享环境克隆→checkout head sha→真实 pytest（`TORCH_DEVICE_BACKEND_AUTOLOAD=0`）；green→squash 并；红⊆main 红债（test-id 精确比较）→放行；真红→自动修复单；环境抖动→PENDING 下周期重试。缓存 per-sha 6h，预算 12 验证/周期，8 库基线 4 线程并行。
- **试点战果**：18 PR 并 main / 冲突 0 / 零人工介入 / 自愈环实证（红→自动修复→再合）。铺开第一波 32 单（8 库×4）2026-11-06 派发在飞。
- **CI 同池**：16 枚 GitHub Actions 自托管 runner（8 库×2）部署于 99 开发同容器，与本机共享 python3.11/torch2.7.1(loong64/SDAA)/pytest——自测≡CI 同一失败词汇，零镜像构建。

### 质量与治理机制

- **质量宪法 R1-R5**：R1 门必须能失败；R3 一票否决；R5 honest-FAIL 不可覆盖；R1-R5 全部可红队验证。
- **质量转向**（2026-11-04）：进度主指标=已合并功能的独立参考复核；PR 分诊五级（R1-R3/RA/RC）+验证专员线。
- **自治组织治理 AOG**：SPEC v1.0 五阶段（审计→M01-M08 机制→五闭环→四中心→三场景）；三层运行：层2 全自动（含元守护自愈）、层1 抽样、层0 残差上报 owner。
- **第三方复现官**：盲序/append-only/strike 开除制；17 份假报告已剔除；自查 result 不可信、必独立复算。
- **论文生产线**：TensorPapers 域+4 席+防造假 v2（数字必须来自实际运行输出）。

### TensorPlatform / TensorPhysics

- 生产部署在役（launch8010 配方）；mission 协议（claim SKIP LOCKED/心跳/预算/审批链）、append-only 事件流、stage_promotion 审批链全在产。
- R1-R7 重构收官：契约表、领域边界反转、物理缝隙守卫、科研闭环首跑。
