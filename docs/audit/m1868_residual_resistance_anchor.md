# m1868 · 阻力「唯一精度门」三路对撞审计

> mission **m1868**（models 席自主工时）· 仓 TensorPlatform · 分支 `agent/m1868` · 2026-11-01
> 工具 `tools/audit/resistance_anchor_m1868.py` · 台账 `artifacts/m1868/resistance_anchor.json` · 测试 `tests/test_residual_resistance_anchor.py` · 图 `artifacts/m1868/resistance_anchor.png`

## ① 案例介绍

平台判定「阻力精度」的唯一闭环是 `POST /ship/benchmark_validate`：拿生产端点的 RT 与注册表参考值比较，误差 >15% 判 FAIL。这条链上其实有**三个各自独立的 RT 来源**，本单让它们在同一组输入上对撞，回答一个问题：**这条门到底有没有一个可对的真值？120% 的分歧该归给谁？**

| 参数 | 值 |
|---|---|
| 船型 | KVLCC2 主尺度（注册表 `kvlcc2_full` 的 params 逐字段一致） |
| L × B × T | 320.0 × 58.0 × 20.8 m |
| Cb / ∇ / 排水量 | 0.8098 / 312,621 m³ / 320,437 t |
| 设计航速 / Fn | 15.0 kn / 0.1377 |
| ρ / ν / g | 1025 kg/m³ / 1.1883e-06 m²/s / 9.81 m/s² |
| 注册表参考值 | RT = **2500 kN**，容差 ±15% |

## ② 怎么做的（三路对撞 + 8 条独立锚点）

- **L（live）**：`POST /api/v1/calculations/resistance`，实跑 10 个航速点（5–18 kn）；
- **R（reference kernel）**：仓内 `backend/api/holtrop1984.py`（纯 Python、论文系数链），按文件路径装载绕开 DB 依赖，同参数离线复算同一航速栅格；
- **G（gate）**：`backend/services/ship_proxy.py::BENCHMARK_REFERENCE['resistance']['kvlcc2_full']`；
- 锚点全部是恒等式或无量纲物理判据，**不引入任何文献常数**（避免用我的记忆当基准）。

| 锚点 | 判据 | 容差 | 结果 |
|---|---|---|---|
| A1 | ITTC-57 摩擦线 CF=0.075/(log₁₀Re−2)² | 2 % | **PASS**；CF=0.0014010，相对误差 0.0278 % |
| A2 | 分解可加性 RT=RF+RR | 1e-6 | **PASS**；相对误差 0.00e+00 |
| A3 | 力-系数恒等式 R=c·½ρV²S（三分量逐一） | 1 % | **PASS**；最差 0.009 % |
| A4 | 摩擦线含 ITTC-78 ΔCF 粗糙度增量 | 2 % | **PASS**；相对误差 0.0086 % |
| A5 | 隐含形状因子 (1+k)=(RT−RR)/(½ρV²S·CF) 落在肥大型船体带 | 1.25–1.55 | **PASS**；(1+k)=1.285 |
| A6 | 三路 RT 在 ±15 % 内两两一致 | 15 % | **FAIL**；live +120.5 %，ref kernel +30.2 % |
| A8-L | live：Fr→0 时 RR/RF 必须塌缩（兴波消失） | ≥5× | **FAIL**；塌缩 1.55×（设计 Fr 2.678 → 低 Fr 1.725） |
| A8-R | ref kernel：Fr→0 时 RW/RF 必须塌缩 | ≥5× | **PASS**；塌缩 557212723.1×（设计 Fr 0.02443 → 低 Fr 0.00000000） |

## ③ 计算结果（程序化注入，零手抄）

| RT 来源 | 15 kn 的 RT [kN] | 与注册值误差 | 平台 15 % 门 |
|---|---|---|---|
| L live 端点 | 5,513.5 | **+120.5 %** | FAIL |
| R 仓内参考实现 | 1,744.6 | **+30.2 %** | FAIL |
| G 注册表 | 2,500.0 | 0 % | 基准 |

L 与 R 互相分歧 **216.0 %**：三路两两都不在 ±15 % 内 → **这条门当前没有一个三方都能对的真值**（这正是 `WITHHELD` 的正确用法）。

| 量 | live | ref kernel | 比值 |
|---|---|---|---|
| 总阻力系数 CT | 0.006545 | 0.002143 | **3.05×** |
| 剩余项占比 (RT−RF)/RT | 0.725 | 0.124 | 5.84× |
| 剩余/摩擦比 | 2.634（RR/RF） | 0.0178（RW/RF₁₊ₖ） | 147.8× |

## ④ 归因（本单的实质增量）

**判决：THREE_WAY_DIVERGENCE**；分歧定位在 **live endpoint residual term (Rr/Cr)**。

- 两条内部路径在同一输入上 CT 相差 **3.05 倍**（0.006545 vs 0.002143），分歧全部落在「剩余项」：live 的剩余项占 RT **72.5 %**，参考实现只占 **12.4 %**；
- 摩擦线（A1）、力-系数换算（A3）、粗糙度增量（A4）、分解可加性（A2）全部 PASS → 「密度 / 湿面积 / 航速 / 单位」这些最常见的锅**已被排除**；
- **A8 是决定性的**：Fr→0 时兴波阻力物理上必须消失。live 的 RR/RF 从设计 Fr 的 2.678 只掉到 1.725（塌缩 1.55×），说明它那个 `rr` **不是造波项**，而是一个近似与航速无关的项被摊在「剩余阻力」名下；参考实现塌缩 557212723.1×，行为符合造波阻力的物理；
- 由 (1+k) 反解 = 1.285（肥大型船体经验带 1.25–1.55），live 把本该进粘性项的额度挤出带外，进一步坐实「剩余项被虚增」。

**因此：live 端点 RT 高 120 % 是真缺陷，不是判据冤枉；但注册值 2500 kN 也未被仓内参考实现（1745 kN，+30.2 %）证实 —— 这条门缺的不是更宽的判据，而是一次原始船模试验表的逐字溯源。**

## ⑤ 注意点 / 局限 / 适用范围

- **这是 code-to-code + 恒等式审计，不是实验对标**：本单不声称 RT 绝对精度达标，只声称「三路在 ±15 % 内两两不一致，且 live 的剩余项违反 Fr→0 消失性」。绝对真值仍需拖曳试验表。
- A5 带 1.25–1.55 是肥大型船体形状因子的经验区间，只做「是否在带内」的二值裁决，不作精度声明。
- A8 用「塌缩 ≥5×」这种量级门槛，避免给兴波阻力设定伪精确带宽；它只能否证量级错误，不能给出正确的 Cr 值。
- 参考实现自身有已文档化简化（rhow=1、LR≈L、短船 Ca 修正缺省、不适用于潜艇外形）；这些是 <1 % 量级的简化，解释不了 3× 的 CT 差（其 CF 自校验误差 0.00e+00 %）。
- 注册值 2500 kN 的原始出处（哪一次 Holtrop 运行 / 哪张表）仍未逐字溯源，本单只用参考实现佐证其量级，**该溯源欠账仍在**。
- `POST /ship/benchmark_validate` 在部署实例上返回 **404**（路由未挂载）：这条唯一的阻力门当前没有任何进程在跑 —— 红门没人跑 = 没有门。
- 修复点在船体性能平台仓的 resistance 内核，按 repo whitelist 不在本仓改，另派修复单。

## ⑥ 误差判定

| 关键量 | 基准 | 误差 | 是否 <3 % |
|---|---|---|---|
| CF（live） | ITTC-57 解析式 | 0.0278 % | **是** |
| RF（live） | ½ρV²S(CF+ΔCF) | 0.0086 % | **是** |
| CF（ref kernel） | ITTC-57 解析式 | 0.00e+00 % | **是** |
| CT（live） | 仓内参考实现 | 205 % | **否** |
| RT（live） | 注册表 2500 kN | **+120.5 %** | **否（≫15 %，不可接受）** |
| RT（ref kernel） | 注册表 2500 kN | **+30.2 %** | 否 |

显式回答：**关键量 RT 的误差为 +120.5 %（live）与 +30.2 %（ref kernel），不满足 <3 %，也不满足平台 15 % 门槛 → 生产端点的阻力实现不可用于精度判决。**摩擦线部分（CF/RF）误差 <0.01 %，可用。
