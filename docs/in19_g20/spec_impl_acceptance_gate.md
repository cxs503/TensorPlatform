## 2. 怎么做的：证据优先，判定离线

### 2.1 判据先于动手（Q1）

动手前把五项判据逐条翻译成**可机器裁的量**，并写下通过条件：

| 判据 | 可机器裁的量 | 通过条件（预注册） |
|---|---|---|
| E1 | 本波 succeeded 单覆盖率、pending 记录可审计率、两路复算一致性、与上游快照的逐格差 | 覆盖 =100%、pending 100% 留 `reason_source`、两路自洽，且快照差能被状态演进解释 |
| E2 | 真实贡献主体按政策阶梯推出的档位上界、准入判定计数、派发矩阵两方向是否都有格 | ≥1 真实案例（≥2 真实主体）、两侧俱全、判定随档位变化 |
| E3 | 账本哈希链重算、周报声明数字 vs 账本复算 | 链 ok 且 ≥1 份非空周报数字全一致 |
| E4 | S-N 记录合法性（等级/E 级/量测/根因/证据引用/不计成果） | ≥1 条合法记录，且目标未全达成（真失败） |
| E5 | 两路独立分层计数对拍、Σ计数 = 梯内记录数、四中心载荷 + SQL 交叉核对 | 对拍一致、Σ恒等、四中心可核、缺失如实声明 |

### 2.2 证据链（审计链）

判定输入只有一份离线 bundle `artifacts/in19_g20/evidence/`：

1. `upstream/`：从上游各 mission 工作树**按字节复制**的 17 个证据文件，逐文件 sha256
   ＋所在分支 commit 记入 `provenance.json`。本次采集到的上游提交：
   `m5018@913cd559`（Q1）、`m5019@394be693`（Q2）、`m5025@04b78ce5`（Q3）、
   `m5023@ff249935`（Q8）、`m5024@f13b0ec2`（Q9）、`m5026@a24190a8`（Q6）；
2. `db_facts.json`：对平台库 `tensorplatform` 的**只读** `COPY (SELECT …)` 事实快照
   （`tensor_dev_missions` 状态、`outcome_evaluations` 全表），SQL 文本随结果落盘，
   任何人可用同一条 SQL 重放。

因此验收门是**纯函数**（bundle → 判定）：结论可离线复算；上游事后改分支，sha256 立刻
指出改了什么；验收门**不写库、不做迁移**（静态护栏测试 `test_gate_never_issues_writes`
守着），所以它无法"自证通过"。

### 2.3 判定器实现要点

* **E1 复算而非信任**：拿上游快照钉住的窗口 mission_id，用**两条独立实现**
  （`Counter` 计数 vs 逐 mission 集合过滤）重算 `(grade, e_level, status)`，再与快照
  逐格对拍。本波结果为：两路自洽 ✅、与快照差 27 格 ❌ —— 于是判定器**必须解释这个差**：
  窗口内现有 31 行、状态含 `candidate/confirmed/rejected`（快照期只有 `confirmed`），
  即记录在快照之后被**重评**过 ⇒ 判 `stale_explained`（快照只能当时点对拍），
  而不是把差抹平、也不是把快照当"复算失败"。
* **E2 用上界而非点估计**：库里没有"复现失败率／虚标计数"事实列，于是不可导出指标一律按
  "通过"处理，得到**档位上界**，再与两条上游的准入映射对撞，逐真实主体给出判定。
* **E3 独立重算哈希链**：`entry_hash = sha256(prev + canonical(row − entry_hash))` 逐条重算
  548 条；再把周报声明的条目数/审查数/生产数/治理秒数与账本复算对拍（时长给 0.05 s
  容差，计数必须严格相等）。
* **E4 机器化 S-N 合法性**：`grade∈{S4,S5}`、§7.1-9 的 S4⇒E≥2／S5⇒E≥3、`honest_fail=true`、
  `result_status=failed*`、`counted_as_output=false`、`root_cause≥40` 字符、≥2 条可落地证据、
  且**目标未全达成**（否则"失败单"是假的）。
* **E5 分层不加权可证**：两路实现互相对拍 + Σ格值 ≡ 梯内记录数 —— 整数计数之和恒等于
  记录数，从结构上排除权重/归一/排名折算；同时把 candidate 162 条与 rejected 13 条
  按 §7.1-9 **显式剔除并留数**，不悄悄丢弃。
* **未实现也算合规**：`implemented=false` 的中心不判缺陷，但必须"如实声明"
  （`not_implemented[].reason` 非空），且 `status=not_implemented` 的指标不得填 0
  （填 0 = Mock 冒充 → 直接 FAIL）。

## 4. 注意点（踩坑 / 局限 / 适用范围）

1. **平台是活系统，快照会过期**：首版判定把 E1 判 FAIL（当时覆盖 2/8），随后平台完成
   评价流部署与全量重评，同一批窗口 id 被改写。这教训直接固化进判定器：快照只作**时点**
   对拍，复算以"两路自洽"为准，且**过期必须留证**（偏差格数、状态集合、行数增长）。
2. **周报时长必须带容差**：初版把 577.317 s 与周报 577.3 s 判为不一致（FAIL）。周报把秒数
   四舍五入到 0.1 s，比对要给 0.05 s 容差，计数仍必须严格相等。
3. **`implemented=false` ≠ 缺陷**：初版 E5 要求四中心全部 `implemented=true`，把"如实声明
   未接入"误判为失败。SPEC §14 要的是"禁止 Mock 冒充"，不是"不许缺失"。
4. **S-N 记录与量测工件同目录**：判定器按 `ticket_id + grade` 字段甄别，量测文件
   （`EP001_measurements.json`）会被跳过而不是当成非法记录。
5. **补记 ≠ 实时**：覆盖 100% 只证明"记录在"，不证明"实时在记"。滞后已量化（最大
   259.5 min）并写进 findings；要断言实时性，需运行面 hook 的可观测证据，本门不给。
6. **"四中心可访问"是载荷级证据**：平台后端 `:8001` 判定时刻未监听，未做在线探活；
   以 m5023 的真实载荷快照 + SQL 交叉核对（44/44）为证，探活不参与判定。
7. **验收门不写库**：FAIL 项只能由上游修，验收门无法自证通过 —— 设计约束，不是遗漏。
8. **适用范围**：判定绑定 bundle（已入仓）；平台继续演进时，用同一命令重跑采集+判定即可
   得到新时点结论，旧 bundle 仍可复算出旧结论（可对比）。

## 5. 误差判定（逐项，显式回答"是否 <3%"）

本门关键量是**计数与判定的精确性**，不是连续物理量：

| 关键量 | 基准 | 实测偏差 | 是否 <3% |
|---|---|---|---|
| S×E 分层计数（1453 条，20 格） | 本门两路独立实现互相对拍 | 0 格偏差（0.0%） | ✅ 精确相等 |
| 账本条目数 | 周报声明 548 | 548（0） | ✅ 精确相等 |
| 审查事件数 / 生产事件数 | 周报声明 372 / 176 | 372 / 176（0） | ✅ 精确相等 |
| 治理耗时 | 周报 577.3 s | 577.317 s（+0.029%） | ✅ |
| 四中心指标 | SQL 交叉核对 44 项 | 44/44（0 项偏差） | ✅ |
| 哈希链完整性 | 548 条独立重算 | `broken_at=None` | ✅ 无断链 |
| 评价覆盖率 | 应由 succeeded 单全覆盖（100%） | 8/8 = 100% | ✅ |
| 记录实时性 | 应≈0 滞后（实时在记） | 6 单滞后 3–4 h（最大 259.5 min） | ❌ **不达标**（已披露，非本门可修） |
| 上游统计快照时效 | 应与库内一致 | 逐格差 27（同批记录已被重评） | ❌ **快照过期**（要求上游刷新） |

结论：**"统计可复算"误差 0%（远优于 <3%）；"记录在"覆盖 100%；但"实时在记"与"上游快照
时效"两项不达标，已作为 findings/limitations 显式列出，不计入 PASS 的粉饰。**
验收门的意义就在于把这几类差异分开说清楚，而不是用一个"达标"把它们盖住。
