# m9107 跨战役知识蒸馏成熟化：从局限/下一步/honest FAIL 自动生成提案种子

> 判据数字全部由 `tools/knowledge_distill/m9107_acceptance.py` 从流水线返回值
> 程序化汇总进 `runs/m9107/acceptance.json`；本报告只引用，不手抄。

## 0 摘要

把「战役收口后手抄各节点结论」换成机器可复算的蒸馏链：报告解析（结构化字段 + markdown 小节双通道）→ 三通道文本特征（TF-IDF 字符 n-gram / 子词哈希嵌入 / 词元 IDF 加权通道）→ 余弦 DBSCAN（邻域半径按 k-距离分位点自适应）→ 簇凝聚度过滤 → 与既有提案池的新颖性双约束门控 → 逐条目 sha256 溯源链。

两条链的判据全部通过：**合成夹具**（10 份模拟报告）解析覆盖率 1.000、4 簇真值一致性 1.000、3 个有效提案种子；**真实语料**（300 份 `work/*/report.json` + 17607 条既有提案/案例参考）601 条抽取条目 → 131 条去重条目 → 26 簇 → 19 个过门种子。

## 1 案例介绍

**问题**：战役 DAG 每个节点交付后，验收报告第 5 节（注意点/局限）与第 6 节（误差判定）里沉淀了大量「能力缺口 / 下一步 / 诚实的失败」；下一波播种时这些信息通常靠人或智能体手抄整理，既不可复算，也会被记忆式自述污染。本节点把这件事实体化为一条可机器复核的流水线。

**输入语料（两条链）**

| 链 | 报告 | 参考池 | 真值 | 用途 |
|---|---|---|---|---|
| 合成夹具 | 10 份 `tests/fixtures/knowledge_distill/reports/*.json` | 1 份合成提案 | 16 条条目级真值 | 判据 (a)(b)(d) 机器可核验 |
| 真实语料 | 300 份 `/root/tp-agent/work/*/report.json` | 1 个目录（17607 条） | 无（人工抽检 20 簇） | 真实缺口 → 真实提案种子 |

**参数表**（`DistillParams`，指纹 `5b2075b40c36c52e…`；未知字段/越界值直接报错，不静默忽略）

| 参数 | 值 | 作用 |
|---|---|---|
| `ngram_min/ngram_max` | 2/3 | 字符 n-gram 区间 |
| `tfidf_weight` | 0.5 | 组合余弦中 TF-IDF 的权重 |
| `emb_dim` | 256 | 子词哈希嵌入维度 |

**工具链**：Python 3.11 标准库（无第三方推理依赖）+ pytest 9 + coverage 7；域中立由 `tools/audit/domain_leak_scan.py` 机器裁决。

## 2 怎么做的

### 2.1 报告解析（`extract.py`）

* **结构化字段通道**：递归遍历 JSON，键名归一化后匹配 limitation / next_step / honest_fail 及中英别名；值支持 str / list / 嵌套 dict，指针形如 `$.review.limitations[0].text`，可回原文定位。
* **markdown 小节通道**：真实 `report.json` 多数只有正文，缺口写在「注意点（…局限…）/ 下一步 / honest FAIL」小节里；标题关键字由参数注入（解析器不含任何域词）。条目按 bullet（含全角序号）与空行切块。
* **过滤**：占位符（`-` / `无` / `n/a`）、以冒号收尾的小节引导语、markdown 表格行与分隔行、长度不足的碎片一律不进条目（实测这些碎片曾把 30 条条目串成一个内聚 0.08 的假簇）。
* **降级**：读不出/非 object 的 JSON → `status=unparsable` + `errors`，绝不抛栈；占位符属输入质量问题记 `warnings`，与硬错误分开统计。
* **脱敏**：口令/令牌/私钥类明文在抽取时就地抹成 `<REDACTED>`（真实报告里出现过明文数据库口令；产物要进仓库与报告，脱敏是硬要求），条目带 `redacted` 标记。
* **全局去重**：按条目文本 sha256 合并（同文条目保留全部来源与出现次数）。真实语料 601 条 → 131 条去重条目（4 组重复；最大的一组是同一份报告被复制多次）。

### 2.2 特征（`features.py`）

* `char_cos = w·cos(TF-IDF 字符 n-gram) + (1-w)·cos(子词哈希嵌入)`；
* `jaccard`：字符 3-gram 集合 Jaccard（对模板句敏感）；
* `token_similarity`：词元 = ASCII 词 + CJK 二元字，取 `max(IDF 加权 Jaccard, 长度比达标时的 IDF 加权包含度)`。长度比门是必需的：短片段与长句共享一个词元时包含度会直接给 1.0（历史缺陷，见 §5）；
* `pair_metric = max(三通道)`：与平台既有 `tools/proposal_seeding/match.py` 的多通道取最大同口径；三路值逐对可查（`full_components`）。

### 2.3 聚类（`cluster.py`）

* 余弦距离 DBSCAN，确定性：点按输入序处理、簇号按首个核心点递增，同一输入连跑两次逐字节相同；
* 自适应半径：k-距离（k = min_samples-1）分布取 0.6 分位点，估计时剔除零距离（同文条目会把半径压成 0）；
* 凝聚度门：簇内平均相似度 < 0.2 的簇退回未归属、不出种子（真实语料实测挡掉单链串联式假簇，见 `clusters.json.dropped_low_cohesion`）；
* 簇画像：成员、平均簇内相似度、代表点（medoid，并列取最小索引）；有真值时给主导标签与主导率。

### 2.4 新颖性门控（`novelty.py`）

* 参考池：既有提案池 + 已验证案例目录，JSON/JSONL 递归抽文本键、markdown 按段落切块；每条参考带路径与 sha256；
* 逐候选算 `max_sim`（三通道取最大）与 `mean_sim`（全部参考，含零相似）；`novelty = 1 - max_sim`，须 `≥ 0.55` **且** `mean_sim ≤ 0.4`（只卡最大值会放行单条相近、其余全像模板的伪新颖）；
* 两级检索：词元通道对全部参考精确计算，前 128 条再算字符级三通道；等价性抽检见 §6（39/40 完全一致，最大偏差 0.009119）。

### 2.5 溯源链（`pipeline.py`）

* 每个种子带 `sources[]`：节点 ID / mission_id / 报告路径 / 报告 sha256 / JSON 指针 / 原文引用 / 引用 sha256 / 同文出现次数；
* `seed_digest = sha256(title + gap_description + repo/domain hint + kind_counts + 排序去重的来源 sha256 集合)`，来源顺序不影响身份；
* 运行级 `MANIFEST.json` 给每个产物文件的 sha256，本次 `manifest_sha256 = dbea95b563be8cba…`。

## 5 注意点（踩过的坑 / 局限 / 适用范围）

**踩过的坑（每条都有对照修复）**

1. **包含度把长链拉爆**：IDF 加权包含度对「短片段被长句包含」直接给 1.0，真实语料把 30 条无关条目串成一个内聚 0.08 的簇。修复：长度比门 + 加权 Jaccard 打底，并加簇凝聚度门。
2. **同文重复压塌自适应半径**：同一份报告被复制多次时 k-距离分布被零距离占满，自动 eps 退化成 0（曾把 601 条切成 4 个巨型簇）。修复：文本 sha256 全局去重 + 估半径时剔零距离。
3. **markdown 表格与引导语残片混进条目**：表头行与引导语残片会被切成条目并互相串簇。修复：表格行/分隔行、冒号收尾残片、过短碎片全部过滤。
4. **真值粒度错配**：一个节点常同时报多个议题，用节点级真值会把跨议题条目算成串簇（一致性被误判为 0.25）。修复：支持条目级真值（`truth_by_item`），同一批簇的一致性回到 1.0——说明低分是标注口径问题而非聚类坏了，也说明判据必须写明真值口径。
5. **判据 (b) 的无证据即通过漏洞**：早期实现里「没给真值」会被算成 ok=True。修复：真值与人工抽检两档证据缺一即判不通过（`judged_by=none`）。
6. **两级检索的近似**：1.7 万条参考上逐条算字符三通道单查询 6.8 s，改为词元全量 + 头部 128 条精确；抽检最大偏差 0.0091，小于门控余量 0.061，不改变任何裁决。

**局限（诚实申报）**

* 词法/子词近似**没有同义改写召回**：换词（如热加载 vs 热更新）实测只给 0.07~0.12，会留在未归属里。真要语义召回需注入预训练向量（接口 `HashedEmbedding.from_vectors` 已留，本次未接任何外部模型，故不宣称语义能力）。
* 部分簇是**同一类陈述**（如误差判据条目）而非同一缺口：能合成判据清单式种子，但不足以直接变成一条可执行提案——这是表面相似 ≠ 同一缺口的固有边界。
* 参考池只覆盖既有提案与已验证案例目录，且提案池里仍有大量跨波次重复模板，mean_sim 因此被稀释（真实语料 mean_sim 仅 0.00483），不利于识别换个说法的重复；故同时给出最近邻 `max_sim` 与原文匹配证据。
* 真实链只按路径排序跑前 300 份报告，未覆盖全量 `work/m*/report.json`；全量跑受参考池索引时间限制（1.7 万条约 60 s/次）。

**适用范围**：任何在报告里写了局限/下一步/FAIL 的战役收口都能直接复用；换语种或换写法密度只需改 `markdown_section_aliases` 与阈值，代码无需改动。

## 6 误差判定

本例**没有物理基准量**（无解析解/实验/文献对照），原因如实声明：这是平台机制任务，输出是提案种子与判据数字，不存在可与实验比对的物理量。因此**是否 <3% 的物理误差标准不适用**；改用两级替代口径：①机器判据相对阈值的余量；②同一聚类结果在两种真值口径下的差异。

| 判据 | 实测 | 阈值 | 余量 | 是否满足 |
|---|---|---|---|---|
| (a) 解析覆盖率 | 1.0000 | ≥0.90 | +0.100 | 是 |
| (b) 簇一致性 | 0.9500 | ≥0.80 | +0.150 | 是 |
| (c) 平均相似度 | 0.0048 | <0.40 | 0.395 | 是 |
| (d) 种子产出 | 19 | ≥3 | +16 | 是 |
