## ① 案例介绍

对象是平台自身的**派单决策面**：蒸馏引擎从已交付节点的 limitation / next_step / honest_fail 抽提案种子后，平台要决定「先派哪一单」。本节点把两件事接起来并用真实派单日志做时序评估：
* 任务日志：12145 条（15 个仓，2026-10-29T01:01:03.319587+00:00 → 2026-11-10T22:57:07.354537+00:00），有结局标签 11316 条（通过 8604 / 失败 2712，通过率 0.760339），删失 829 条，有成本标签 9584 条。
* 蒸馏语料：400 份 report.json，解析覆盖率 1.0，条目 1253 条（{'limitation': 1250, 'next_step': 3, 'honest_fail': 0}），通过新颖性门控的种子 4 / 7。

## ② 怎么做的

1. **解析**：复用 `tools.knowledge_distill`（TF-IDF×子词哈希嵌入×词元 IDF 三通道、余弦 DBSCAN、凝聚度门、novelty≥0.55 / mean_sim≤0.40 双约束门控）。
2. **派单日志**：`tools.seed_dispatch/log.py` 只取派单时刻字段（repo / budget / 任务书长度 / 是否子单 / co_repos）+ 严格回看的仓通过率、仓近 40 条失败率、平台近 100 条失败率、滑动池新颖性；`result.*` / `status` / `finished_at` 只做标签与成本。
3. **排序**：L2 逻辑回归估 P(验收通过)（确定性全批梯度），对数线性成本模型估 tool_calls，`EVOI = P·max(novelty, 0.05)/cost`；按时间切 5 窗做严格 walk-forward。
4. **off-policy**：时间桶为 slate，日志实际只派 FIFO 最早一条；`π0=(1-ε)softmax(β·FIFO 优先度)+ε/|s|` 做 IPS/SNIPS，报 ESS 与重叠度。
5. **泄漏审计**：事后字段扰动替换 → 特征矩阵必须逐字节相同、指标漂移 ≤ 容差；再把结局当特征注入，指标必须跳变（否则审计无鉴别力）。

## ⑤ 注意点与局限

1. **反事实不可知**：真实日志只记录派了谁。(d) 用「已执行条目全部有结局」做直接 precision 评估；IPS/SNIPS 只在「每轮只派一单」设想下给出一致估计，且 propensity 是**重建**（FIFO softmax 假设）而非记录 → IPS 数字只能当敏感性分析（本次 IPS 5.65 远超 1，是权重方差爆炸的直接证据，ESS 仅 28.6）。
2. **系统态混杂**：审计期内出现过磁盘写满导致的 worker 崩溃（记 failed），与候选质量无关；已用 `f_global_recent_fail`（平台近 100 条失败率）作为显式协变量吸收一部分，但未建模。
3. **新颖性是代理**：日志侧是滑动池余弦（回看近似），种子侧是蒸馏层三通道最大相似度；两者同向但不同源，只可比序不可比绝对值。
4. **成本口径**：历史用 tool_calls（事后，仅作拟合标签），候选用对数线性预测；token/时长型成本未纳入，故 EVOI 的「单位成本」是算力代理而非资金。
5. **种子样本极少**：400 份报告只产出个位数通过门控的种子，排名统计意义薄弱，只作派单顺序建议。
6. **口径敏感性**：见上表——四个变体增益均在 3.8~6.0 pp，说明 (d) 未达标不是口径选坏的偶然。
