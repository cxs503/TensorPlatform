## 3. 独立重建的执行路径（与作者描述对照）

```
POST /api/v1/datasets/{id}/upload
  ├─ _user(Authorization)          认证：缺/伪造 → 401（P04 实测 OK）
  ├─ _row(dataset_id)              存在性：无 → 404
  │    ✗ 无 ds["owner"] == user 比较 → 任意已认证主体可写任意数据集（P02）
  ├─ stored_name = file.filename   客户端名直接用作落盘名（未取 basename、未白名单）
  ├─ target = UPLOAD_ROOT/stored_name   ✗ 穿越：filename="../../x.csv" → UPLOAD_ROOT/../.. （P05）
  ├─ target.parent.mkdir(parents=True, exist_ok=True)   ✗ 穿越时还会静默造目录
  ├─ content = await file.read()   全量入内存/磁盘暂存，无 Content-Length 校验、无 413 分支（P01）
  ├─ target.write_bytes(content)   直接截断写终态文件（非 tempfile+os.replace）→ 并发撕裂读（P10）
  ├─ _count_rows(target)           ✗ 校验发生在写之后：失败 → 422 但文件已被覆盖（P06/P09）
  └─ UPDATE datasets SET path,rows ✗ 校验失败时不更新 → meta 与文件内容不一致（P06 实测 rows=2 / 文件是垃圾）
GET /api/v1/datasets/{id}/download  ✗ 无认证依赖（_user 未调用）→ 匿名可读（P03）
```

作者在总结里写「多租户隔离、尺寸上限、失败回滚、断点续传均已按 AC 实现」。逐条对照后，这四句**全不成立**，
且都不是「实现不完善」，而是**代码里根本没有对应分支**（`runs/static_checks.txt`：`413`=0、`os.replace`=0、
`403`=0、`Content-Range` 仅出现在我写的注释里=1、`owner` 出现 3 次全部在 SQL 里、无任何比较）。

## 4. 严重度排序的发现（每条绑定证据与复现）

复现命令（任一探针）：

```bash
cd docs/skills_training/P07-1 && python3 probe_upload.py     # 全量
python3 -m pytest candidate/test_upload_happy.py -q          # 作者套件：3 passed（信息量=0 关于契约）
```

### C1（critical，已确认）跨租户越权写：任意登录用户可覆盖他人数据集
- 期望：403；观测：**200**，alice 的文件被 bob 覆盖，sha `2a2b86e74ffd → b37573c84e63`。
- 证据：`runs/probe_output.txt` P02；代码 `upload_service.py:103-104`（`_user()`/`_row()` 之后无任何属主比较）。
- 影响：数据投毒 / 静默篡改训练集，属安全缺陷而非风格问题。**阻塞发布。**

### C2（critical，已确认）路径穿越：客户端 filename 决定落盘位置
- 期望：400/422 且不写出上传目录；观测：**200**，文件落到 `UPLOAD_ROOT/../../p07_escape.csv`（真实）`exists=True`；探针实测路径解析结果为 `/tmp/p07_escape.csv`（沙箱外）。
- 证据：P05；代码 `upload_service.py:105-106`（`target = UPLOAD_ROOT / stored_name`）+ `:108` 的 `mkdir(parents=True)`。
- 影响：可在服务进程可写的任意路径写文件（配合 `.csv` 后缀限制不严可进一步做覆盖/触发下游解析）。**阻塞发布。**

### C3（critical，已确认）失败上传摧毁既有版本（无原子性、无回滚）
- 期望：422 且原文件字节不变（AC-5）；观测：**422**，但 `roll.csv` 已变为 `b'\x00\x01\x02\xff'`，
  且 `meta.rows` 仍为 2 → 元数据与文件内容**互相矛盾**。
- 证据：P06；代码 `upload_service.py:109-113`（`write_bytes` 在 `_count_rows` 之前，异常直接 `raise`，无 restore 路径）。
- 影响：一次坏上传即造成**不可恢复的数据丢失**；下游清洗/训练读到的是垃圾而元数据说「2 行」。

### H1（high，已确认）无尺寸上限，200 MiB 单请求被接受
- 期望：>100 MiB → 413 且不落盘；观测：**200**，`bytes=209715200` 落盘 200 MiB（流式发送，客户端内存恒定）。
- 证据：P01（真实 socket 流式上传 + `Content-Length` 正确声明）；代码无 `MAX`/413 分支（静态证据 grep）。
- 影响：磁盘/带宽耗尽（DoS 面无成本）。注：starlette 的 `UploadFile` 以 SpooledTemporaryFile 暂存，
  **内存**增长并非无界（>1 MiB 落临时盘）——这是**推断**（基于 starlette 1.0 行为，未单独测量 RSS），
  故我只把「磁盘/配额」计入事实，「RSS 随文件线性增长」标为未验证。

### H2（high，已确认）匿名可读：下载端点无认证
- 期望：401/403；观测：**200**，无 `Authorization` 头拿到 16 bytes 内容。
- 证据：P03；代码 `upload_service.py:123-128`（`download_dataset_file` 只做 `_row()`，未调用 `_user()`）。
- 影响：跨租户数据泄露，与 C1 组合即「读+写」双失守。

### H3（high，已确认）续传语义被静默忽略：分片被登记为完整版本
- 期望：202/409，或按 `Content-Range` 偏移拼接；观测：**200**，声明 `bytes 0-7/1000` 的 8 字节分片被写成
  「当前完整数据集」（`rows=1, bytes=8`），后续下游会把 8 字节当完整数据。
- 证据：P07；代码 `upload_service.py:96-120`（端点内无 `Content-Range`/偏移状态读取）。
- 影响：比「不支持续传」更坏——**静默错误**：客户端以为续传被接受，服务端把残缺数据当成品。

### H4（high，已确认）同数据集并发写无互斥，且存在撕裂读
- 期望：一 200 一 409；观测：`codes=[200, 200]`，并发期间读者观测到 3 个中间态，含 `e3b0c44298fc`
  （= sha256 空串，即 truncate 后尚未写入的窗口）与一个非终态 sha。
- 证据：P10；代码 `upload_service.py:109` 的 `write_bytes`（`open(...,'wb')` 截断）+ 全文件无锁。
- 影响：读者（下载/下游解析）可能拿到空文件或半文件；「文件-元数据」一致性无并发保证。

### M1（medium，已确认）类型伪装被内容校验挡住，但残留垃圾文件且 meta/文件不一致
- 观测：`spoof.csv`（二进制）→ **422**（NUL 检查生效，值得给分），但文件留在 UPLOAD_ROOT（`exists=True`）且
  `meta.path=None`。
- 影响：磁盘垃圾 + 后续「按目录扫描」的模块可能把垃圾当数据集；属 C3 的同一根因（写在校验前）。

### M2（medium，已确认）中断上传不破坏既有版本，但完全没有续传能力
- 真实 socket 半途 RST（5 MiB / 40 MiB）：原 `abort.csv` 字节不变（**这是实现的一个缓解事实**），
  服务端无偏移/续传令牌，未完成的 40 MiB 请求体整体丢弃 → 大文件弱网成本全由客户端承担。
- 诚实标注：此项是「AC-6 未实现」，而非「实现错误」，与 H3 合起来才构成完整判断。

### L1（low，推断/静态）缺结构化日志与审计
- 契约 §4 要求失败写入结构化留痕；代码 `logging` 出现 0 次，失败路径仅 `raise HTTPException`。
  证据强度：静态计数（不是运行时观测）→ 标注为**静态确认、影响面低**。

### 未被采纳为缺陷的「疑似问题」（避免凑数）
- `Content-Type` 未校验：契约 AC-8 只要求「扩展名与内容一致性」，`_count_rows` 的 NUL/行数检查覆盖了主要意图，
  仅「.jpg 改成 .csv」这类仍会 422；不单列缺陷，并入 M1。
- 404 泄露数据集存在性（枚举）：与 C1 相比边际价值低，列为**建议**，不列为缺陷。

## 9. 本次训练的元结论（可复用打法）

1. **「有认证」≠「有授权」**：本候选的 `_user()` 覆盖率看起来 100%，但属主比较缺失让写权限等于「任意登录」。
   审计口径必须是「每个状态变更处是否比较了主体与资源属主」，而不是「是否调用了认证依赖」。
2. **先写后校验是回滚缺陷的根因形状**：只要 `write` 在校验之前且目标就是终态路径，就同时得到「数据丢失 +
   残留 + meta 不一致」三个症状。识别形状比逐个症状有用。
3. **静默忽略协议头比不支持更危险**：`Content-Range` 被忽略导致分片被登记为完整版本，远端无法感知；
   正确失败模式是显式 501/400。
4. **happy-path 测试的绿色是可证伪的**：拿探针去跑，绿色套件与契约违反可以同时成立；评审报告要给出这种
   并存的具体读数，而不是「建议加强测试」。
5. **同一作者不能当自己评审**：本次把独立性缺陷写在 §1 而不是藏起来，并用可重放探针把结论锚在命令输出上，
   这是弱化（不是消除）同源偏差的唯一可行办法。
