# 文件上传端点 · 测试清单（自拟基线，评审前冻结）

> 由 `design_spec.md` 的 INV 反推得到，评审前冻结；评审以其为覆盖基准。
> P0=阻断级（INV 违反/安全）、P1=重要（数据完整性/可用性）、P2=体验/一致性。

## A. 现有测试面盘查（评审起点）

| 项 | 方法 | 结论 |
|---|---|---|
| 是否有该模块的测试文件 | 全仓检索 `file_upload` / `uploaded_files` / `/upload` 于 `tests/`、`backend/tests/` | 见 `probe_results.json` → `baseline.coverage_scan` |
| 是否有 happy-path 用例 | 同上 | 同上 |

> 题设为「只有 happy-path 测试」；实测覆盖见 probe 输出，若为 0 则比题设更差，评审按「完全无测试」定级。

## B. 用例清单

### B1 尺寸上限（INV-1，T4）

| ID | 用例 | 期望 | 优先级 |
|---|---|---|---|
| S-01 | 恰好 `MAX_FILE_SIZE` 字节 | 接受（契约：`≤`） | P1 |
| S-02 | `MAX_FILE_SIZE+1` 字节 | 4xx 拒绝 | P0 |
| S-03 | 远超上限的大文件（按比例缩小复现） | 读取到上限附近即中止，不整包缓冲 | P0 |
| S-04 | 空文件 0 字节 | 接受或明确 4xx（契约须一致） | P2 |
| S-05 | 批量中单文件超限 | 该文件记 error，其余成功 | P1 |

### B2 类型（INV-2，T3）

| ID | 用例 | 期望 | 优先级 |
|---|---|---|---|
| T-01 | 白名单扩展名 `a.csv` | 接受 | P0 |
| T-02 | 大写 `A.CSV` | 接受 | P1 |

| T-04 | 空文件名 | 4xx，不落盘 | P0 |

### B4 授权（INV-4，T1/T2）

| ID | 用例 | 期望 | 优先级 |
|---|---|---|---|
| A-01 | 无凭据 `POST /upload` | 401/403 | P0 |

### B5 中断 / 续传 / 幂等（INV-5、INV-6、INV-7，T5/T6）

| ID | 用例 | 期望 | 优先级 |
|---|---|---|---|
| R-01 | 传输中断（流读到一半抛错） | 无半成品文件残留（临时文件 + 原子 rename） | P0 |
| R-02 | 上传 `Content-Range` 分片 | 支持续传，或明确 501 | P1 |
| R-03 | 同一文件重传两次 | 幂等或显式重复（响应可区分） | P2 |
| R-04 | 下载 `Range: bytes=0-3` | 206 + 正确字节 | P1 |
| R-05 | 中断后清单/统计不出现幽灵条目 | 一致 | P1 |

### B6 完整性 / 错误语义（INV-5、INV-8、INV-9）

| ID | 用例 | 期望 | 优先级 |
|---|---|---|---|
| C-01 | DB 插入失败时上传结果 | 500 且回滚物理文件；**禁止** 200 + 文件落盘 | P0 |
| C-02 | DB 不可用时 `GET /files` | 5xx，不得 200 空集 | P1 |
| C-03 | `GET /files/{id}` 字段对齐 | 每个字段语义正确（尤其 `uploaded_at`） | P1 |
| C-04 | 迁移种子行是否进入用户列表/统计 | 不进入 | P1 |
| C-05 | 错误响应是否含内部路径/SQL | 不含 | P1 |
| C-06 | 下载缺失物理文件 | 404，且记录状态可自愈 | P2 |
| C-07 | 删除后记录与文件同时消失 | 一致 | P1 |
| C-08 | 迁移在 SQLite 后端可执行（NFR-4） | 可执行 | P2 |

## C. 覆盖矩阵模板（评审阶段填充）

每条用例记录：`实际观测` / `判定（OK / CONFIRMED_DEFECT / NOT_IMPLEMENTED / ACCEPTED_RISK / UNTESTED）` / `证据`。
判定标准：**CONFIRMED_DEFECT 必须有可复现的探针输出**；仅靠读码推断的一律记 `UNTESTED_RISK`（含理由与补测成本）。
