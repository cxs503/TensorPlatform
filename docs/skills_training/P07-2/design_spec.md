# 文件上传端点 · 设计规格（自拟基线，评审前冻结）

> 本文件是评审者**在阅读实现细节之外**先独立写出的「该端点应当如何工作」的契约。
> 目的：把评审从「代码看起来对不对」变成「实现是否满足契约」，避免以实现为中心的事后合理化。
> 冻结时间：评审开始前；冻结后不再修改，评审结论只引用不改写。
> 适用对象：`backend/api/file_upload.py`（路由 `/upload`、`/upload/batch`、`/files*`、`/download/{id}`、`/stats`），
> 存储 `backend/migrations/011_file_upload.sql`，挂载点 `backend/api/domain/tools.py`。

## 1. 范围与非目标

**在范围内**：单文件上传、批量上传、文件元数据查询、文件列表/分页、物理下载、删除、统计。
**非目标**：对象存储后端、病毒扫描、内容级预览、跨租户配额计费。

## 2. 接口契约

| 端点 | 方法 | 语义 | 成功码 |
|---|---|---|---|
| `/upload` | POST | 单文件上传（multipart，字段 `file` + 可选 `category`） | 201 |
| `/upload/batch` | POST | 多文件上传，逐文件独立成败 | 200（部分成功） |
| `/files` | GET | 分页列表，可按 `category` 过滤 | 200 |
| `/files/{id}` | GET | 单条元数据 | 200 |
| `/download/{id}` | GET | 物理下载，支持 `Range` | 200 / 206 |
| `/files/{id}` | DELETE | 删除记录 + 物理文件 | 200 |
| `/stats` | GET | 汇总统计 | 200 |

## 3. 不变量（INV）——评审的核心判据

| 编号 | 不变量 | 违反后果 | 验证方式 |
|---|---|---|---|
| INV-1 | **尺寸上限**：单文件字节数 ≤ `MAX_FILE_SIZE`；超限返回 4xx，且**在读取超过上限+ε 字节后立即中止**（流式），不得先整包缓冲 | 内存耗尽型 DoS | 边界值 + 实际读取字节计量 |
| INV-2 | **类型白名单**：以最终扩展名判定，大小写不敏感；不在白名单 → 4xx | 可执行/主动内容落盘 | 扩展名矩阵 |
| INV-3 | **目录围栏**：写入路径必须落在 `UPLOAD_DIR/<category>` 内；`category` 必须是枚举白名单，不得由客户端决定路径分量 | 任意路径写入（可覆盖系统文件） | 穿越载荷 |
| INV-4 | **授权**：所有端点要求已认证主体；文件级访问受 owner/共享策略约束；不得存在无主体可读写删的端点 | 未授权读写删（IDOR） | 无凭据/他人凭据 |
| INV-5 | **原子性**：文件与 DB 记录同生同灭；中断（客户端断开、磁盘满、DB 故障）不得留下可见半成品 | 孤儿文件/孤儿记录、配额虚耗 | 中断注入 + DB 故障注入 |
| INV-6 | **幂等/去重**：契约须明示——重复上传同内容要么返回既有记录，要么显式接受重复 | 存储放大、重复计费 | 二次上传 |
| INV-7 | **可续传**：要么支持分片/`Content-Range` 续传，要么明确 501，并说明客户端重试语义 | 大文件弱网不可用、静默重复 | 头字段探测 + 路由表 |
| INV-8 | **错误语义**：内部细节（路径、SQL、堆栈）不外泄；依赖故障返回 5xx，**不得以空集 200 伪装成功** | 排障误导、信息泄露 | 故障注入 |
| INV-9 | **列表/元数据一致性**：字段按名绑定（不依赖列序）；种子/占位数据不进用户视图；分页契约稳定 | 前端错渲、展示幽灵文件 | 字段对齐 + 种子行 |
| INV-10 | **下载安全**：`Content-Disposition` 为 attachment、`nosniff`；仅在声明 MIME 白名单内内联；Range 正确切分 | 存储型 XSS、断点续传失效 | 下载头 + Range |

## 4. 非功能要求

- **NFR-1 内存**：并发上传内存上界 ≈ 并发数 × 分块大小，与文件尺寸**无关**。
- **NFR-2 并发**：同内容并发上传不产生损坏文件（写临时文件后 `rename` 原子落位）。
- **NFR-3 可观测**：失败有结构化日志（含 trace id），拒绝原因可分类计数。
- **NFR-4 可移植**：迁移脚本须在平台支持的两种后端（PostgreSQL / SQLite 本地部署）可执行。
- **NFR-5 配额**：可按主体限总量/限速（与本端点身份模型配套）。

## 5. 威胁模型（评审用）

T1 匿名攻击者（无凭据、可枚举 ID）；T2 已认证低权用户（越权读他人文件）；
T3 恶意文件名/表单字段（路径穿越、扩展名伪装）；T4 资源耗尽（大文件、批量条数、并发）；
T5 网络不稳定客户端（中断、重复提交）；T6 运维故障（DB 不可用、磁盘满）。

## 6. 验收定义

- 所有 P0 用例通过方可发布；任一 INV 违反即阻断。
- 「只有 happy-path 测试」= 不满足发布门槛：P0 负例覆盖率必须 > 0。
