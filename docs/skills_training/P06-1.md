## 1. Impact / containment（影响与遏制）

- **[F]** 缺陷对象：`docs/skills_training/toy_service/toy_service.py` 的 `list_books()`，
  一个 10 条目的玩具图书目录分页服务（无网络、无外部状态、无生产消费者）。
- **[F]** 症状（作为"用户报告"注入）：客户端按服务端广告的 `total_pages` 遍历
  `page=1..total_pages` 时，永远拿不到目录末尾的条目（10 条只拿到 9 条）。
- **[I]** 影响面：任何"信任 `total_pages` 翻页"的客户端会静默丢失尾部
  `total % per_page` 条数据；数据不重复、不损坏，仅**不可达**。
- **[F]** 遏制/回滚决策：无需遏制（无生产流量、无数据写入）；回滚方案见 §10。
  诊断在隔离目录 `docs/skills_training/toy_service/` 内进行，未触碰任何生产代码。

## 4. Causal explanation（因果机制）

- **[F]** 失败行：`toy_service.py:30`（修复前）`total_pages = total // per_page`。
- **[I]** 因果链：`//` 是向下取整。当 `total % per_page != 0` 时，
  `total_pages` 比真实页数少 1 → 服务端**广告**的页范围比实际需要的少一页 →
  守规矩的客户端遍历 `1..total_pages` 时，最后一个不满页（含尾部
  `total % per_page` 条）永远不被请求 → 尾部条目不可达。
- **[I]** 为什么"失败行"不是根因的全部：切片逻辑（`start=(page-1)*per_page`）
  本身正确（P1 证明直接请求第 4 页能拿到 Book 10）；根因是**被违反的不变量**
  "每个条目必须被 `1..total_pages` 中恰好一页覆盖"，而该不变量由
  `total_pages` 的计算方式破坏。栈/失败行只是线索，根因在语义层。
- **[A]** 假设：客户端行为符合"只遍历广告页范围"的常规约定（复现器即按此实现）。

## 6. Minimal fix（最小修复与路径）

- 路径：`docs/skills_training/toy_service/toy_service.py:30`，**1 行**改动：
  ```python
  # before
  total_pages = total // per_page
  # after
  total_pages = (total + per_page - 1) // per_page  # ceil: last partial page must be advertised
  ```
- **[F]** 无其他改动（`git diff` 仅该行）；未做任何无关清理。
- **[I]** 选 `(total + per_page - 1) // per_page` 而非 `math.ceil(total/per_page)`：
  纯整数运算，避免浮点除法在超大 total 下的精度问题；`per_page>=1` 已由参数校验保证。
