# 验证欠账台账的可判性审计（m1860, verifier 席）

**一句话**：`tools/validation_debt_ledger.py` 已经把 101 篇平台报告的「局限/待办」节抽成 564 条欠账，
但**抽取器本身从未被计量**。本单用人工标注的 45 条样本测出它的条目精度为
**88.89%**（45 条里 5 条假欠账），修好规则后升到
**100.00%**，且在 40 条真欠账上**零召回损失**。欠账优先级队列因此可以当数据用。

## 1. 为什么做这件事（而不是再做一条物理复核）

owner 的优先级是「验证欠账 > 功能补全 > 失效测试」，而**"哪条欠账最重"这个输入本身来自台账**。
台账一旦有噪声，派单队列就被稀释（例如把 `✅ 质量守恒验证（漂移 <0.1%）` 当成欠账，
把数据表每行 `| +15.5 | 56.39 | 0` 当成欠账）。计量工具 = 给优先级队列校准刻度，属于最上游的验证欠账。

## 2. 方法

1. **固定语料**：从平台 API 拉最近 101 篇报告（`/tensor/reports`，markdown 全文逐篇取回），
   冻结成快照后再跑抽取器——避免分页窗口在审计期间漂移（首次抽样就撞到过一次：报告 1289 掉出窗口）。
2. **抽取器双版本**：HEAD 版（`git show HEAD:tools/validation_debt_ledger.py`）作对照，工作树版作处理组，
   同一份语料各跑一次。
3. **人工标注 45 条**（分层随机：seed=42 从 564 条里抽 45 条，逐条读原文判 DEBT/NON_DEBT）：
   标注结果与理由落在 `artifacts/validation_debt_m1860/gold_eval.json`，可复算、可推翻。
4. **判定口径**：NON_DEBT = ①数据表行（只有数字，无命题）；②已闭合的过程坑（"已修正/已改为…"）；
   ③正向自证句（✅/✓/"No test was rewritten"）。**字形不作判据**：`❌ 高 Re 湍流：未覆盖` 是真欠账，
   用"❌ 就丢"的规则会把欠账藏起来。

## 4. 规则改动（最小面）

| 位置 | 改动 | 依据 |
|---|---|---|
| `CLOSED_HINTS_RE` | 增 `已改为/已修正/已纠正/已重跑/已回填`、`already fixed` | 抽检 S35/S40 是"已修好的过程坑" |
| `POSITIVE_HINTS_RE` | 增 `✅`、`no test was rewritten/xfailed` | 抽检 S23/S45 |
| `table_row_kind()` | 表格行三分类：numeric（丢）/header（丢）/text（**保留且自成一条**） | S16 数据行；风险登记行 R11 是真实欠账，且不能与上一行续接 |
| `LIVE_DEBT_GUARD_RE` | 正向/闭合规则只在条目"没有活口"时生效 | 保护 "✅ 已可用，但 X 尚未验证" 这类复合句 |
| `stats` | 新增 4 个 `dropped_*` 计数 | 丢弃必须可见，否则等于静默改口径 |

回归：`tests/test_m1860_debt_ledger_precision.py`（14 条断言，含**反例**：
❌ 标记保留、复合句保留、风险登记行保留且不粘行、诊断计数自洽），
与既有 `tests/test_validation_debt_ledger.py`（31 条）合计 **45 passed**。

## 5. 注意点 / 局限

* **样本只有 45 条**，精度点估计的 95% Wilson 区间约 ±9 pp（88.89% 一侧），
  因此"精度提升到 100%"只能读作"在这 45 条上假欠账清零"，不能读作平台级 <3% 的精度声明。
* **无学科标签率仍 ~59%**：这些多为数值/V&V 元陈述
  （网格收敛、网格分辨率、算力限制），不是漏标物理学科，但会让"按学科排队"失效——本单未改学科词表，
  以免为了降未标率而发明标签（会把"溃坝网格收敛"硬塞进某个学科）。
* **表格行判据用"有没有数字格"分界**：文字型风险登记行保留是对的，但若某篇报告把欠账写成
  "编号 | 描述 | 概率 | 影响"里带数字概率，可能被当数据行丢掉——这是显式接受的取舍，已由丢弃计数可发现。
* 台账仍是"报告自述"的集合，**不代表欠账真实存在**；本单只校准"能不能拿去排序"。

## 6. 误差判定

| 关键量 | 基准 | 本单 | 相对误差 | <3%? |
|---|---|---|---|---|
| 抽取条目精度（45 条人工标注） | HEAD 88.89% | 100.00% | 提升 11.11 pp | **不适用**：这是测量量对另一测量量的比较，不是对参考解的误差；n=45 的统计区间 ≈±9 pp，远大于 3%，故不宣称 <3% |
| 真欠账召回（40 条 DEBT） | HEAD 40/40 | 40/40 | 0 | **是**（逐条在台账中可检索，误差 0/40 = 0%） |
| 条目总数可解释性 | HEAD 无记账 | 丢弃 43 条逐项计数 + 剩余 536 条 = 579 条候选 | 记账残差 0 | **是** |

## 8. 给下一个 verifier 的线索

1. 复发欠账簇里"平台治理"桶占最大一块（99 条），它吞掉了本可归属到
   阻力/稳性的条目——**学科词表与治理词表的优先级**值得单独立审计。
2. `artifact_refs_missing` 里仍有跨仓假阳性（`papers/tools/*.py` 属 TensorPapers 仓）：多搜索根尚未接进 CLI 默认值。
3. 报告语料窗口恒为最近 100 篇（API `total` 恒 1 的分页怪象）：**欠账台账天生只看近因**，
   建"全历史入库 + 窗口快照"才能做时间序列复算。
