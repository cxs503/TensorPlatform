# 跨战役重复劳动冗余聚类审计：冗余簇识别 + 预算浪费账本（P393W2-N02）

**结论（先看这里）**：verdict = `PASS`。强阈值 0.85 下：标注集 F1 = **1.0000**（判据 ≥0.85）、难负例误报率 = **0.0000**（判据 ≤0.10）、预登记字面重播组召回 = **1.0000**（4/4 组）、域词命中 = **0**、账本复算相对误差 = **0.0**。**但**同题改写召回（17 对人工判定）在强阈值下 = **0.0000**——这是本节点最重要的诚实结论：词面法在「改标题/改表述」的重复上几乎全漏。

## ① 案例介绍（被审计对象与参数）

被审计对象是平台真库里的战役节点：**2451 个节点 / 269 个战役计划**（覆盖偏差见⑤）。每个节点的「任务书」= 节点名 + `metadata.goal`；节点挂靠 mission 提供资源证据
（`mission.budget` 与起止时间）。审计目标是回答三个问题：

1. **有哪些节点在做同一件事**（冗余簇）——不是「主题相近」，而是「交付物/判据同一」。
2. **这些重复劳动烧掉了多少资源**（wall-clock 实耗与预算上限），占总盘子的比例。
3. **每个簇该怎么处置**：keep（保留 keeper）/ merge（已花成本，证据并入 keeper，禁止重跑）/ archive（零成本重复件，直接撤单）。

| 参数 | 取值 | 作用 |
|---|---|---|
| 字符 n-gram 长度 | 4 | 相似度口径（复用 tools.proposal_gate.textsim） |
| containment 权重 | 0.700 | score = max(jaccard, w·containment) |
| 长度比门 | 0.500 | 过短/过长对不启用 containment、且直接剪枝 |
| 最短参与长度 | 40 字符 | 标题级短文本不参与成对判重 |
| 倒排 df 截断 | 600 | 高频 shingle 无语料判别力，等价数据驱动的停用词 |
| 候选上限/节点 | 400 | 近似最近邻的每节点候选预算 |
| 强阈值 / 弱阈值 | 0.85 / 0.7 | 强边聚类治理；弱边只列待复核 |
| 标注集规模 | 100 | A 结构正例 + B 同计划设计分工对 + C 抽样负例 |
| 冻结判据 | F1 最大（tie-break：F1 最大者；F1 并列取更小的阈值（更保守地抓冗余），仍并列取更小的网格值） | 预登记后冻结 |

## ② 怎么做的（方法 / 流程 / 关键设置）

- 1 快照（只读 GET，sha256 钉死）
- 2 索引（字符 4-gram 倒排 + 长度过滤）
- 3 近似最近邻 + 上界剪枝 → 精确打分的候选对
- 4 阈值聚类（强边连通分量 / 弱边待复核）
- 5 成本归集（node→mission wall-clock）+ 冗余成本
- 6 100 对标注集 → 阈值扫描 → 冻结
- 7 判据对账（F1 / 组召回 / 难负例误报 / 域词 / 账本复算）

**索引与候选**：2440 个节点入索引（11 个因过短未参与），倒排 shingle 数 540366，倒排候选对 516384，经「上界剪枝」（`score ≤ max(s/maxsize, w_c·s/minsize)`）后精确打分 280 对（下限 0.5）。候选召回对账：分桶抽检 16 对桶内真值 → recall = **1.0000**；同计划全对枚举 10629 对（真值 0 对）→ recall = **1.0000**。

**聚类**：强边（score ≥ 强阈值）取连通分量 → 一个簇 = 一次治理动作的作用域；簇内最弱边分 `min_edge_score` 供人工复核链式传递风险。弱边（弱阈值 ≤ score < 强阈值）不并簇，单列待复核。

**账本**：`wall_seconds_actual = (actual_end|finished_at) − (actual_start|created_at)`（两端齐全才算，开区间记 0 并标记 `open_interval`，避免用 wall-clock 造不可复现数字）；预算上限取 `mission.budget`。簇级成本 = 全簇求和 / keeper 求和 / 冗余（非 keeper）求和，逐字段独立复算。

**标注与冻结**：A 组（结构正例）= 剥掉波次标签后节点名逐字相同；B 组（难负例）= 同计划内不同 ext_id、不同标题的设计分工对（模板化正文把它们的词面相似度抬高，是阈值最易误报的位置）；C 组 = 跨计划稳定抽签（sha256）且 score<0.35。80 对经审计者逐对读标题复核，0 处改判，复核留痕在 `artifacts/redundancy_audit/annotations_overrides.json`。

## ⑤ 注意点（陷阱 / 局限 / 适用范围）

- **F1 任务书里的 `campaign_nodes.budget_actual` 不存在**：节点表无预算列（真库字段实测：`actual_end, actual_start, created_at, deliverables, ext_id, goal, metric_names, mission_id, name, node_id, plan_id, repo, status, text`）。本账本改用 node→mission 的 wall-clock 实耗 + mission.budget 预算上限，并在报告 JSON 里逐字段标注来源。
- **F2 plan 级 budget_actual 恒零**：269/269 个计划的三项预算实耗全 0（从不回写）。
- **F3 ext_id 不是全局任务 ID**：63 个 ext_id 在跨计划时指向多个不同节点名（例：`IN30-N01`）。用「ext_id 相同」判重会误判，本审计的 A 组因此只用「剥波次标签后同名」。
- **F5 同名也可能不同题**：同一节点名在跨计划被复用时会混入异题节点（本报告的同名组口径里就有 1 组因此只拿到 0.750 的组级召回），所以预登记真重复组改用「名 + 正文逐字相同」的**字面重播组**，并同时披露同名组口径作为对照。
- **F4 负面侧难度天然很低**：候选池里难负例最高分只有 0.591，0.70 以上的对经逐对复核全为真重复——这不是阈值调得好，而是语料本身被重播灌满了重复。因此 precision 侧的 1.0 不应被读作「方法很准」。
- **计划覆盖有偏**：`GET /tensor/campaigns/plans` 无 offset 参数、单次上限 100，只能按 status 分档取并集（active/completed 各 100、draft 69），是「最新 100 活动 + 最新 100 已完成 + 全部草稿」的有偏切片，不是全库普查。
- **标注无第二方**：A/B/C 规则是确定性的，但 80 对人工复核、17 对改写压力集都由同一 agent 判定，没有独立标注者，故 F1 的置信区间未做（也无法做）双标注一致性校正。
- **改写召回是能力边界，不是调参问题**：词面相似度对「换词/换语序/长短标题」不敏感（score 会掉到 0.45-0.70），要真正治理这类重复，需要判据层面的指纹（交付物路径 + 度量名 + 基准名），这是本节点给出的下一步（见⑥）。
- **账本口径**：`wall_seconds_actual` 是 mission 生命周期（含排队/等待），不是纯算力；开区间节点记 0，故冗余成本是**保守下界**（707 个节点区间未闭合）。

## ⑥ 误差判定（逐项 vs 基准，显式回答是否达标）

| 量 | 实测 | 基准/判据 | 误差或差值 | 是否达标 |
|---|---|---|---|---|
| 强阈值 F1 | 1.0000 | ≥0.85 | +0.15 余量 | ✅ |
| 难负例误报率 | 0.0000 | ≤0.10 | −0.10（更优） | ✅ |
| 字面重播组召回 | 1.0000 | ==1.00（4/4 组） | 0.00 | ✅ |
| 域词命中 | 0 | ==0 | 0 | ✅ |
| 账本复算相对误差 | 0.000 | ==0（记账单位 1e-3 s） | 0.000e+00 | ✅ |
| 同题改写召回（强阈值） | 0.0000 | 无判据（诚实披露） | −1.00（0/17） | ⚠️ 能力边界 |

**关于「是否 <3%」**：本节点的关键量是分类指标与账本一致性，不是物理量对基准的百分误差，因此「<3%」不直接适用；等价的硬口径是：①账本复算相对误差 **= 0.000e+00**（远小于任何 % 门）；②判据余量 F1 1.00 vs 0.85。**唯一明确不达标的是同题改写召回（0/17）**，已在⑤与结论里如实标注，不作粉饰；把它写成「能力边界」而不是「误差」，是因为词面法在设计上就不覆盖该带（<0.70）。
