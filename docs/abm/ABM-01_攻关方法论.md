# ABM-01 · 攻关方法论（七环闭环 × 八项基本能力）

> 规范族 ABM 第 1 件。上位文件：`ABM-00_总纲.md`（owner 2026-11-07 方法论令整理，原文权威）。
> 本件把总纲 §2（七环）与 §3（八能力）展开为可执行的操作定义：每一环有输入/动作/产出/出口判据，
> 每一项能力有触发时机/交付物/反模式。配套：问题树模板与子问题验收问题表见 `ABM-02`，
> 五角色与六维评价见 `ABM-03`，假设登记与证据链见 `ABM-04`，分级见 `ABM-07`。

## 0. 适用范围

- 适用：高难攻关任务（campaign 节点中 node_type=task 且预期 S≥S2 者）。
- 不适用：例行维护、纯文档搬运（走常规 Mission 流程，S1 判据即可）。
- 铁律（总纲 §8 原则 1）：**允许失败，不允许伪造成功**——可以没解决，必须诚实报证据和局限。
  失败返回假设/调查/实验环，**不许把失败包装成完成**。

## 1. 七环闭环（操作定义）

闭环顺序：**问题定义 → 现状调查 → 提出假设 → 实施实验 → 独立挑战 → 结果验收 → 知识沉淀**。

| 环 | 名称 | 输入 | 关键动作 | 产出（工件） | 出口判据（机器可裁优先） |
|---|---|---|---|---|---|
| R1 | 问题定义 | 任务单/campaign 节点 goal | 写问题陈述；定验收标准；过问题树（ABM-02 §1） | 问题陈述 + 验收标准（判据数字） | 验收标准可机器裁（测试/参考值/守恒量）；判据先于动手 |
| R2 | 现状调查 | 问题陈述 | 基线四问（§3）；查已有代码/文献/成熟方案 | 基线报告（差距 + 拟突破的具体限制） | 四问全答；差距可量化；无「重实现一遍宣称突破」风险 |
| R3 | 提出假设 | 基线报告 | 每次重要修改带假设五件套（§4）；登记（ABM-04 §1） | 假设登记条目（prereg，先于实验） | 五件套字段齐；预测已盲（登记时间戳早于实验启动） |
| R4 | 实施实验 | 假设登记 | 按证伪实验设计执行；原始结果落盘 | 原始计算结果 + 实验配置（可复现） | 原始数据可溯源（五元链，ABM-04 §3）；配置可复现 |
| R5 | 独立挑战 | 实验结果 + 假设登记 | 挑战者独立判断（ABM-03 §2）；分歧走区分实验不投票 | 挑战意见（引数字/工件路径） | 挑战意见有出处；分歧已裁决或已设计区分实验 |
| R6 | 结果验收 | 全部证据 | 按 S×E 定级（ABM-07）；S3+ 独立审查（ABM-05） | 验收记录（S×E + grade_reason） | S×E 合法组合（SPEC v1.2 §7.1 规则 8/9）；S3+ 有独立审查记录 |
| R7 | 知识沉淀 | 验收记录 | 沉淀三资产（ABM-06 §1）；失败进失败知识库（ABM-06 §2） | 知识/工具/经验资产 + 失败条目 | 资产已登记平台（不留对话上下文）；失败条目字段齐 |

**失败返回路径**：R5/R6 判失败 → 回到 R3（假设错）/ R2（调查不足）/ R4（实验设计错），
并在失败知识库登记（ABM-06 §2）。**禁止**：改到测试碰巧通过即宣称成功；把 L1 包装成 L4（ABM-07 §4）。

**Agent 的任务不是生产代码，而是产生经过验证的知识和能力**——代码只是载体之一（总纲 §2）。

## 2. 八项基本能力（操作定义）

| # | 能力 | 触发时机 | 交付物 | 反模式（禁止） |
|---|---|---|---|---|
| C1 | 问题拆解 | 动手前（R1） | 问题树（ABM-02 §1 模板） | 见任务就写码；跳过问题树直接编码 |
| C2 | 建立基线 | R2 | 基线四问回答（§3） | 重实现一遍然后宣称突破 |
| C3 | 假设驱动 | 每次重要修改（R3） | 假设五件套（§4）+ 登记条目 | 改到测试碰巧通过；无假设的「优化」 |
| C4 | 交叉验证 | R4-R5 | 五角色分工记录（ABM-03 §1） | 作者自证；挑战者沦为帮作者完善方案 |
| C5 | 对照实验 | 多路线并行时（R4） | 六维评价表（ABM-03 §3） | 按 PR 先后定胜负；只跑自己路线 |
| C6 | 失败分析 | 任一环失败 | 结构化失败记录（ABM-06 §2） | 失败不留痕；后来者重复踩坑 |
| C7 | 分层验收 | R6 | S×E 验收记录（ABM-07） | 把 L1 包装成 L4；自报 S2+ 无对照基线 |
| C8 | 知识复用 | R7 | 三资产登记（ABM-06 §1） | 知识留在对话上下文；成功路径不复用 |

## 3. 基线四问（C2 展开）

R2 现状调查必须逐问作答，缺一问不得进入 R3：

| 问 | 内容 | 回答要求 |
|---|---|---|
| Q1 | 最好已知方案是什么？ | 给出方案名/出处（文献或代码路径），说明其能力边界 |
| Q2 | 已有代码到什么程度？ | 指向具体仓/模块/测试；说明已验证到什么证据等级（E0-E4） |
| Q3 | 文献成熟方法是什么？ | 至少一条可对照的成熟方法；注明适用条件 |
| Q4 | 差距在哪？突破哪个具体限制？ | 差距量化（指标+数值）；突破对象是**具体限制**而非泛泛「更好」 |

四问全答 + 差距量化 = 基线成立。基线报告是 R3 的硬前置（机制 A 任务准入，总纲 §5）。

## 4. 假设五件套（C3 展开）

每次重要修改必须带明确假设，五件套缺一不得进入 R4：

| 件 | 字段 | 要求 |
|---|---|---|
| 1 | 理论依据 | 理论/文献依据（引出处）；无依据的猜测须显式标注「探索性」 |
| 2 | 代码位置 | 具体到文件/函数（或「新增模块」+ 契约） |
| 3 | 证伪实验设计 | 什么结果会证伪该假设（可判定的失败判据） |
| 4 | 修改前后预测 | 修改前预测值 + 修改后预测值（**先登记后实验**，预测盲规则 ABM-04 §2） |
| 5 | 数据裁决 | 实验后填写：裁决数据 + 判定（证实/证伪/部分） |

**假设被证伪也是有价值的成果**（总纲 §3.3）：证伪结论按 S-N 否定性成果轨入账（SPEC v1.2 §7.1），
不得删除登记、不得事后改预测。

## 5. 问题树（C1 展开，模板见 ABM-02 §1）

动手前先过问题树，至少覆盖六层：物理机制 / 数值方法 / 实现正确性 / 数值稳定性 / 验证 / 可视化。
每层回答：该层是否可能是瓶颈？判据是什么？——先定位瓶颈层，再在该层提假设。
