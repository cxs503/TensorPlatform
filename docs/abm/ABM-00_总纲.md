# ABM-00 · Agent 攻关方法论总纲（v0.1）

> owner 2026-11-07 方法论令原文整理，原文权威，本纲不改写语义。
> 落库路径（目标）：`docs/abm/ABM-00_总纲.md`；规范族 ABM-01..07 见 §11。

## 1. 核心判断：三种智能

- **单体智能**：靠一个 Agent 的知识、推理、经验解决问题。
- **群体智能**：靠任务分解、专业分工、交叉验证、知识积累、反复迭代解决问题。
- **组织智能**：把成功方法、失败经验、质量标准、协作机制**固化到平台**，使下一批 Agent 做得更好。

**要建设的是第三种。** 不把一百个 Agent 训练成比 ChatGPT 更聪明的单体；建立一套方法论，让一百个能力有限的 Agent 完成单体高能力 Agent 也难独立完成的攻关任务。人类公司管理制度不可直接照搬（Agent 可大量并行/快速重复/随时替换/易产出貌似合理的错误成果）。

**与自治治理 SPEC 的关系**：SPEC 管「组织怎么治理、成果怎么评」；ABM 管「难关怎么攻」。两者共用同一套评价标尺（见 §4）。

## 2. 攻关闭环（七环）

问题定义 → 现状调查 → 提出假设 → 实施实验 → 独立挑战 → 结果验收 → 知识沉淀。
失败返回假设/调查/实验环，**不许把失败包装成完成**。Agent 的任务不是生产代码，而是**产生经过验证的知识和能力**——代码只是载体之一。

## 3. 八项基本能力

1. **问题拆解**：动手前先过问题树（物理机制/数值方法/实现正确性/数值稳定性/验证/可视化…）。禁止见任务就写码。
2. **建立基线**：最好已知方案？已有代码到什么程度？文献成熟方法？差距在哪？突破哪个具体限制？——防「重实现一遍然后宣称突破」。
3. **假设驱动**：每次重要修改必须带明确假设（理论依据/代码位置/证伪实验设计/修改前后预测/数据裁决）。**假设被证伪也是有价值的成果**——防「改到测试碰巧通过」。
4. **交叉验证**：五角色=攻关负责人/理论研究者/实现工程师/挑战者/独立验证者。挑战者有独立判断权，不是帮作者完善方案。
5. **对照实验**：多路线并行竞争（修正现有/换数值方法/参考成熟开源重构），统一六维评价（正确性/精度/稳定性/计算效率/可复现性/适用范围），**证据定胜负，不按 PR 先后**。
6. **失败分析**：失败记录结构化（最初假设/哪个不成立/哪环节/理论错还是实现错还是实验设计错/已证无效路径/后续避免什么）——后来者不重复踩坑。
7. **分层验收**：L1 执行/L2 工程/L3 技术/L4 知识/L5 创造（≡S1-S5，见 §4）。不是每个任务都要 L5，而是**不许把 L1 包装成 L4**。
8. **知识复用**：每次攻关沉淀三资产——知识资产（理论/方法/规律）、工具资产（代码/测试/验证器）、经验资产（成功路径/失败案例/判断规则）——全进平台，不留对话上下文里。

## 4. L1-L5 ≡ S1-S5：标尺统一（关键裁定）

owner 的 L1-L5 分层验收与 SPEC v1.1/v1.2 的 S1-S5 价值分级**同构**：

| owner L | SPEC S | 语义 | 验收要求 |
|---|---|---|---|
| L1 执行成果 | S1 执行性 | 任务完成、可运行 | 完成即证 |
| L2 工程成果 | S2 改进性 | 结构合理、测试过、可复现 | **须对照基线** |
| L3 技术成果 | S3 建设性 | 指标改善超基线 | 须能力可用+登记 Delta+**独立审查** |
| L4 知识成果 | S4 突破性 | 新规律/新方法/可靠结论 | 须声明突破了什么 |
| L5 创造成果 | S5 创造性 | 原创且可推广的新能力 | 须新颖性检索范围 |

**一套标尺两个名字。ABM 全部验收用 S×E（S=创造了什么价值，E=凭什么相信）；不立第二套标尺。S3+（=L3+）强制独立审查。**

## 5. 五平台级机制（须落到工作流/数据结构/权限/质量门，不停留在文档）

- **机制 A 任务准入**：高难任务不直接进编码——先有问题定义、现状调查、基线、验收标准。
- **机制 B 证据驱动**：每个关键结论可追溯到 理论或文献依据 / 代码版本 / 实验配置 / 原始计算结果 / 分析报告（五元链）。
- **机制 C 独立审查**：执行 Agent 不得自批自己的成果；L3+（S3+）必须独立审查。
- **机制 D 动态升级**：多次失败/无法解释异常/缺专业知识时，不许无限重复——可请求更强 Agent/领域专家/重分配/补知识/换技术路线。
- **机制 E 能力评价**：七指标=首次解决率/结果有效率/假设命中率/缺陷发现率/复现成功率/知识贡献率/攻关贡献度。**不评代码量/PR 数/完成率**；防挑简单任务；缺陷发现者不算低产出；禁止加权成单一排名。

## 6. 外部认知支架（六种，按角色差异化）

专业知识包（理论/实现/验证/挑战者**各配不同的包**——同一灵魂可多执行分身，独立判断工作必须不同知识结构与评价视角）/标准攻关流程/专业工具/专家示范案例（优秀+失败各带分析）/独立质量审查/组织知识库。数量的价值不在复制一百个相同的人，而在组织一百个**相互补充、相互质疑**的认知单元。

## 7. 强弱 Agent 能力传递（二期）

强推理层（问题抽象/理论/战略/关键路线）×大规模执行层（调查/实现/实验/独立验证）×组织知识层（验证过的知识/失败记录/工具/能力模型）三层循环：推理指导执行→执行产证据→证据修正推理→沉淀提下一轮。理想态：强模型建初始框架→Agent 学框架并执行→困难时主动暴露→强模型只攻关键瓶颈→指导蒸馏为方法工具→**逐步不依赖强模型持续干预**（能力蒸馏与组织学习）。二期播种（一期四机制+试点验证后）。

## 8. 三原则（写进底层规范）

1. **允许失败，不允许伪造成功**——可以没解决，必须诚实报证据和局限。
2. **允许分歧，不追求虚假共识**——不同结论不用投票裁决，设计能区分不同假设的实验。
3. **评最终贡献，不评表面工作量**——5000 行代码可能零贡献；一行关键数学修正可能决定成败。
