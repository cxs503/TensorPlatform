# ABM-02 · 任务分解规范（问题树模板 + 子问题验收问题表）

> 规范族 ABM 第 2 件。上位文件：`ABM-00_总纲.md` §3.1（问题拆解）/ §5 机制 A（任务准入）。
> 本件规定：高难任务如何拆成可独立验收的子问题，以及每个子问题必须回答的验收问题。
> 配套：七环中 R1/R2 的出口判据见 `ABM-01` §1；假设登记见 `ABM-04`。

## 1. 问题树模板

每个攻关任务动手前必须产出一棵问题树。模板（六层，可按域增层，不得减层）：

```
[根] 任务目标（一句话，含可判定的成功判据）
├── M1 物理机制层：物理图像对不对？（控制方程/边界条件/本构/守恒律）
│     判据：守恒量闭合、量纲一致、极限情形有解析行为
├── M2 数值方法层：离散格式对不对？（格式/阶数/稳定性条件/收敛性）
│     判据：网格收敛阶、CFL/稳定域、与参考格式对照
├── M3 实现正确性层：代码是否实现了方法？（单元实现/索引/边界处理）
│     判据：解析解/ manufactured solution、单元测试
├── M4 数值稳定性层：会不会算飞？（时间步/迭代/病态输入）
│     判据：长时间积分不发散、扰动敏感性、能量行为
├── M5 验证层：结果可信吗？（验证 vs 确认、独立复现）
│     判据：对解析解/实验锚/文献值在声明容差内；独立复现
└── M6 可视化/交付层：结果能被检查吗？（图/数据/报告）
      判据：图带判据数字、数据可溯源（五元链，ABM-04 §3）
```

**使用规则**：
1. 先定位瓶颈层（哪一层最可能是当前失败/差距的来源），再在该层提假设——禁止见任务就写码（总纲 §3.1）。
2. 每层标注：状态（未查/已查/已证伪/已解决）+ 证据指针（工件路径）。
3. 子问题 = 问题树叶子节点；每个叶子必须挂一个验收问题（§2）。

## 2. 子问题验收问题表

每个子问题（叶子）登记一行，缺字段不得进入实施环：

| 字段 | 内容 | 缺省/禁止 |
|---|---|---|
| 子问题 ID | `<任务ID>-Q<序号>` | 必填 |
| 所属层 | M1-M6 之一 | 必填 |
| 子问题陈述 | 一句话，可独立回答 | 禁止「优化一下 XX」式模糊陈述 |
| 验收问题 | 该子问题「做成了」的问句（是/否可裁） | 必填 |
| 参考值/守恒量 | 解析解、实验锚、文献值或守恒量 | 无基准须声明原因（不许含糊） |
| 容差 | 关键量误差阈值（如 <3%） | 必填数字 |
| 依赖 | 前置子问题 ID | 无依赖填 — |
| 可并行 | 是/否（与哪些并行） | 必填 |
| 预期 S 级 | S1-S5 声明（ABM-07） | 必填；S2+ 须对照基线 |
| 负责角色 | 五角色之一（ABM-03 §1） | 必填 |

**最小可证单元**：子问题粒度以「一次实验/一个测试集可裁决」为准；
拆不出验收问题的子问题 = 还没拆到位，退回 R1。

## 3. 分解规则

1. **依赖序**：先 M1/M2（机制与方法），后 M3/M4（实现与稳定），M5 贯穿，M6 收尾。
2. **可并行项**：无依赖的子问题并行派发（campaign DAG 边表达依赖）。
3. **最小可证单元**：每个子问题有独立判据；不允许「整体做完一起看」。
4. **防漂移**：子问题验收只认本行判据；跨子问题的综合结论在 R6 统一按 S×E 定级。

## 4. 任务准入门（机制 A 落地）

高难任务不直接进编码。准入检查单（全过才进 R3）：

- [ ] 问题定义：问题陈述 + 验收标准（判据数字）已登记
- [ ] 现状调查：基线四问（ABM-01 §3）已答
- [ ] 基线：已知最好方案 + 差距 + 拟突破的具体限制已写明
- [ ] 验收标准：机器可裁（测试/参考值/守恒量）
- [ ] 问题树：六层齐，瓶颈层已定位

未过准入门的任务：打回 R1/R2，不得以「先写起来再说」绕过。
