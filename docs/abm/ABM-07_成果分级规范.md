# ABM-07 · 成果分级规范（L≡S 统一映射，与 SPEC v1.2 S×E 同构，不立第二标尺）

> 规范族 ABM 第 7 件。上位文件：`ABM-00_总纲.md` §4（标尺统一，关键裁定）。
> 本件是 ABM 规范族的**唯一分级出口**：ABM 全部验收用 S×E（S=创造了什么价值，E=凭什么相信）。
> S/E 的完整定义引 `docs/architecture/AUTONOMOUS_AGENT_ORGANIZATION_GOVERNANCE_SPEC_v1.2.md`
> §6.2（E0-E4）与 §7（S1-S5 + 判定规则），本件不重定义、不另立标尺。

## 1. L≡S 统一映射表

owner 的 L1-L5 分层验收与 SPEC v1.1/v1.2 的 S1-S5 价值分级**同构**——一套标尺两个名字：

| owner L | SPEC S | 语义 | 验收要求 |
|---|---|---|---|
| L1 执行成果 | S1 执行性 | 任务完成、可运行 | 完成即证 |
| L2 工程成果 | S2 改进性 | 结构合理、测试过、可复现 | **须对照基线** |
| L3 技术成果 | S3 建设性 | 指标改善超基线 | 须能力可用 + 登记 Delta + **独立审查**（ABM-05） |
| L4 知识成果 | S4 突破性 | 新规律/新方法/可靠结论 | 须声明突破了什么 |
| L5 创造成果 | S5 创造性 | 原创且可推广的新能力 | 须新颖性检索范围 |

**声明**：本表与 SPEC v1.2 S×E **同构**，ABM 不立第二套标尺。
任何 ABM 文档/申报中出现 L 级，必须同时给出等价 S 级；只写 L 不写 S 的申报无效。

## 2. 定级规则（引 SPEC v1.2 §7.1，摘要）

1. 按实际成果定级，不按任务难度、Agent 身份或自我评价定级；
2. 提案不等于成果：未验证创意标「创新候选/待验证」，不得直接记 S4/S5；
3. S2 必须有比较依据，S3 必须证明能力真实可用，S4 必须证明突破了什么，S5 必须证明新在哪里；
   「代码量大/PR 多/测试多/用了新技术」均不是升级依据；
4. 维护性工作如实记录，不强迫归入 S2 或虚构能力增量；
5. 成果等级与证据等级分开呈现（如 S3/E2）；任何等级登记至少 E1；
6. S×E 非法组合不计入成果统计（S4 须 E≥2 附对照基线；S5 须 E≥3）；
7. 失败探索可形成 S-N 否定性成果（负面知识轨，计入 Productivity 维度）。

## 3. 申报与审查接口

| 申报 S 级 | 必备证据 | 审查 |
|---|---|---|
| S1 | 交付物与任务要求对应 + 未完成项说明 | 抽检 |
| S2 | 改进前后基线对照（数字） | Execution Audit |
| S3 | 能力契约 + 独立验证 + Capability Delta 登记 | **独立审查（不同模型族，ABM-05）** |
| S4 | 被突破的原有限制 + 可信基线对照 + 关键结论可复现 | 双独立评审 + 盲序 |
| S5 | 发现来源 + 新颖性检索范围 + 可证伪假设 + 证据 | 双独立评审 + 盲序 + 新颖性检索记录 |

## 4. 反包装条款

- **不许把 L1 包装成 L4**（总纲 §3.7）：申报 S≥S3 而无对照基线/突破声明/新颖性检索 → 打回；
- 无对照基线增量严禁自报 S2 及以上（S 分级活例纪律，owner 2026-11-07 令）；
- grade_reason 必须引具体数字/工件路径，空话 = 降级；
- 独立席位按 S×E 复判：auto_scan 只是预筛非终判。

## 5. 统计纪律

- 统计各等级数量/占比/证据成熟度/复用情况/否定性成果产出与复用（SPEC v1.2 §7.2）；
- **不得**将 S1-S5 加权成单一 Agent 排名或直接绑定个人奖惩；
- 分级用于识别：组织是否只在执行既定任务、是否持续建设新能力、是否给突破和创造留出空间。
