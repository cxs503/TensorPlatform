# 报告语料完整性闸门（m2053）

## 1 案例与问题
平台证据 = `tensor_reports` 表的 1382 篇报告；能力分级、复核通过率、验证欠账清偿率（m1996 的 4.02%）、
谱系追溯 KPI（454/499）全部从这张表数出来。此前**没有任何**去重与内部算术一致性检查。本单补这道闸门。

## 2 方法
- **重复发布**：正文 token（CJK 逐字 + ASCII 逐词 + 数字）→ k=5 shingle（blake2b-64）→ Jaccard；
  候选对由 同 mission / 同 scenario_key / 归一化标题（剥 `（m1797）` 标记）生成，避免 O(N²)；
  并查集聚类，簇内 max J ≥ 0.90 判 DUPLICATE_REPUBLISH，0.60–0.90 判 NEAR_DUPLICATE。
- **表内算术自洽**：markdown 表解析成 (表头, 行) → 找「误差%」列 → 机械枚举 (值列, 参考列) 全部组合，
  取复算命中最多者作为该表的标定（命中率 ≥60% 且 ≥3 行才认证）→ 逐行裁决：
  OK / SIGN_CONVENTION / ABS_CONVENTION / ROUNDING_ARTIFACT（印刷精度区间内有解，解析求根）/
  PERCENT_POINT_CONFUSION（stated ≈ |a−b|×100，即 `(a−b)/b×100` 漏了分母）/ MISMATCH。
- 量纲纪律：`%` 与 `‰` 同口径折算（‰×0.1），纯数值单元才参与复算，带单位/区间/斜杠的单元一律不解析；
  标定阶段再卡 `|log10(a/b)| ≤ 2`，防止把 kg 列与 t 列当成 (值, 参考值)。

## 4 抓到的真实缺陷（逐条可复核）
1. **报告 1115/1116（同一重复簇）**：`35.0000 | 44.4235 | +942.35%`。真实相对误差 −21.21%，
   报出值 = |35−44.4235|×100 = 942.35 ⇒ 公式漏掉 `/b`，把「绝对差×100」当成相对误差。
2. **报告 1163**：`0.9111 | 0.65 | +26.11%`。表头写「VCB/d ≤ 0.65 上界」，正确相对越限 40.17%，
   26.11% = (0.9111−0.65)×100 ⇒ 同一类「漏分母」缺陷。**两处独立出现 ⇒ 是缺陷类，不是个例。**

## 5 注意点与局限
- **负结果（如实披露）**：先试过「同 scenario_key 同名指标数值冲突」检测器，在真实语料上给 9 条，
  人工逐条裁决精度 1/9 ≈ 11%（原因：上下文短语"误差"不能指认单一物理量；`report-backfill` 这类
  scenario_key 是桶不是算例）。低精度检测器不能当闸门，故未纳入，只保留零语义判据。
- 被跳过 32798 行：不可认证表（无误差列 / 命中率 <60% / 多百分数列），属能力边界，不冒充缺陷。
- 26 条 ROUNDING 是「中间量被截断到 4 位再算百分数」，不是错；但它说明报告的中间量精度不足以复算声明误差。
- 残余 4 条 MISMATCH 未逐条定性（多为多百分数列的表，标定列选偏），不声称是缺陷。
- 语料在本单执行期间仍在增长（1364→1382 篇），数字以 commit 时的 JSON 为准。

## 6 误差判定（是否有基准？）
本单是**语料一致性审计**，不是物理量预测，无实验基准可比。判定改为**可复算性**：
- 算术判据为闭式恒等式，代码对自身基准的偏差为 **0**（33 条 pytest 全绿，含手算三元组）；
- 缺陷裁决精度：PERCENT_POINT 类 2/2 人工复核为真（100%）；
  MISMATCH 类抽样 16 条中仅 1 条不可用印刷精度解释（≈6% 为真缺陷，故不作为告警输出，只做台账）；
- 是否 <3%：**判据本身无误差**（恒等式），故该项 N/A；检出率口径见上两行。
