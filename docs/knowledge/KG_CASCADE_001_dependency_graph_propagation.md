## 规则 1：级联传播用「最坏短板 max + 边权」，不要用乘积或求和

**机制**：`deg(n) = max_d w(d→n) · max(own_drop(d), deg(d))`，`eff(n) = own(n)·(1−deg(n))`。

**为什么**：正确性依赖是短板效应（任一上游不可信 → 下游不可信）。乘积会把两条各 0.5 的依赖
夸大成 0.25 的"双重惩罚"；求和不满足 [0,1] 有界与单调。`max`+边权同时满足有界、单调、可手算，
且对**有环图**也能用从 0 起单调松弛到不动点的方式收敛（迭代数与收敛标志必须显式返回，禁止
静默截断）。

**推荐流程**：
1. 先把「等级 → 自身置信度」写成显式映射表（配置化，不写死在代码）；
2. 传播算 `deg`，回写等级时用**置信带 + 不得高于自身证据等级**的护栏（级联只能降级）；
3. 手算 3 条链写进基准文件，再让引擎逐节点对比（误差门槛 10%）——这是抓实现 bug（迭代顺序、
   漏传递、基础值取错）最便宜的办法。

**反例/局限**：手算一致（实测 0.0%）只证明"实现 = 规格"，**不证明"规格 = 真实失效统计"**。
边权是未标定先验时，必须在报告里显式声明，不得包装成"精度"。

## 规则 2：「受影响」≠「等级变了」：受影响集合只收置信度下降的节点

**机制**：受影响集合判据为 `max(own_drop, deg) > tol`；事件方向单列 `degrade/upgrade/no_change`
与 `changed_ids`。纯升级事件的受影响清单必须为空、severity 为 `info`。

**为什么**：第一版把事件节点无条件算进受影响清单，导致 `STUB→REAL` 升级也报"受影响 1 条"、
severity 误判，预警语义被污染。升级只改变自身等级，不使任何下游退化。

**推荐流程**：把方向与变更节点做成独立字段，测试同时断言「升级 → affected_count==0」与
「升级 → 不得把下游抬过其自身等级」。

## 规则 3：零领域语义扫描对 ASCII 短词必须用词边界，否则扫描器自己就是噪声源

**机制**：ASCII 词条用 `(?<![a-z0-9_])tok(?![a-z0-9_])`，CJK 词条用子串匹配。

**为什么**：三字母词条（如 `ice`、`ship`）会命中 `service`、`relationship` 这类普通英文单词
内部；第一版扫描把自己写的注释判红（命中 2 条假阳性），如果不加词边界，要么误红整仓，要么
被人为放宽阈值把判据废掉。

**回归保护**：`tests/test_capability_graph.py::test_zero_domain_semantics_scan_clean`（真扫
9 个文件，0 命中）+ `tests/...::test_unknown_level_is_reported_not_guessed`（不认识的值必须报，
不许猜成 WITHHELD）。

## 附：判据必须做破坏性负对照（元规则）

任何"相似度 ≥ 阈值"型判据都要回答：**删几条 / 反向几条会让它掉到阈值以下？** 本单基线 13 条边：
删 2 条 → 0.846（仍过），删 3 条 → 0.769（破阈），反向 3 条 → 0.625（破阈），全边重复 → 1.0
（去重正确）。若破坏后仍全过，该判据是恒真的假阳性来源。实现：
`tools/capability_graph/checks.py::mutation_sensitivity`。
