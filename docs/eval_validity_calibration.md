## ① 案例介绍（学科背景与对象）

本节点评估的不是船体，而是**评价体系本身**：把平台给出的 S×E 判级（S1–S5 成果档 × E0–E4 证据档）当作一个二分类预测器，问它能否预测工件的下游真实命运——合进主干（merge）、合并后回归被回退（rollback）、闸门红被退回重做（rework）、直接丢弃（discard）。若判级与下游结果脱钩，则所有「S 级成果」统计都是自说自话。

**几何/参数对象**：无船体几何；对象是 4117 条有判级的任务记录及其下游事件。评价不需要 Cb/L/B 校验（非几何任务），但需要**标签可观测性**校验——见下表。

## ② 方法（怎么做的）

1. **标签构造**（`tools/eval_validity/dataset.py`，只读）：
   - 平台落账台账 `merge_master_state.json` / `merge_governor_state.json`：`merged*` → merge；merge 之后出现红门/返工派单 → rework（**合并后回归**）；从未 merge 但有红门 → rework；只有排队中间态 → censored。
   - 船仓（本地私有仓、无 PR 闸）合并台账 `ship_merge_ledger.jsonl`：`merged` → merge，`held`/`conflict` → rework。
   - PR 闸回填：仅兜底（见 ⑤ 选择偏倚）。
2. **时间轴**：walk-forward 按**任务完成时刻**排序（不是评价落定时刻）。评价是成批回填的，用回填时刻排序会把十天历史压进几小时，时间窗退化为随机切分。
3. **模型**：主模型 `cell_rate`——训练窗内 `(grade, e_level)` 格子的经验 merge 率（Beta(2) 向 S 边际、再向全局收缩），不预设 S/E 方向与可加性；另跑 `logistic`（S 秩、E 秩两特征）与 `s_rank`（仅 S 秩）作稳健性对照，全报不挑选。
4. **五条判据**：walk-forward OOS AUC、Brier+分箱校准曲线、评分通胀检测、标签置换负控、跨仓一致性。负控把标签置换后**重跑整条管线**（含重训与重切窗）。
5. **工具链**：纯 numpy 实现（无 sklearn 依赖），pytest 24 例，全部只读 psql（SQL 白名单：单条 SELECT/WITH，禁写关键字）。

## ⑤ 注意点（踩过的坑 / 局限 / 适用范围）

1. **评价记录只对 succeeded 任务存在**（待评价记录由 succeeded 派生），因此「任务失败」这一最硬的下游负例根本不在样本里——本校准测的是「已成功任务里，判级能否预测它能否真正落地」，不是「判级能否预测任务成败」。
2. **PR 闸回填是按成功挑样**（240 条里 239 条 merged）：直接用它算校准会把merge 率虚抬到 99.6%。已从主分析剔除，只留敏感性表（表 8）。
3. **生命周期事件不构成下游信号**：全部 110 条 `custody_requeue` 都早于任务 `finished_at`（任务内部重排队），据此判「返工」会造假，故不作为标签来源。
4. **时代混淆**：merge 率在 0.105–0.632 之间随波次跳变，且检查是否红是仓级而非单工件级（一次坏 main 会让整波 CI 全红）。要真正分离判级的边际效应，需要按仓×波次做条件化或加波次固定效应——本节点未做，留作下一步。
5. **时间轴退化风险**：评价 `decided_at` 是成批回填（同一批几百条挤在数小时），故改用任务完成时刻；若未来改成实时评价，两者应一致。
6. **标签口径敏感**：「S 级占比」按严格单档 S1（37.0%）判据触发；若按前两档 S1+S2 则为 100.0%（平台只用这两档，恒为 100%）。两种口径都在 JSON 里，报告不挑对结论有利的那个。
7. **适用边界**：结论只覆盖 GitHub 落账台账与船仓合并台账覆盖的时段（2026-10-30 → 2026-11-07）；台账之前的任务无可观测终局，一律 censored。

## ⑥ 误差判定（对解析基准，逐项）

本文的「基准」不是船模试验值，而是统计量的**闭式理论值**——随机标签下 AUC ≡ 0.5、完美分离 AUC ≡ 1、完美概率 Brier ≡ 0、无泄漏切分必有 max(train_t) < min(test_t)。逐项相对误差如下：

| 自检项 | 计算值 | 解析值 | 相对误差 | 是否 <3% |
|---|---|---|---|---|
| AUC 完美分离（理论 1.0） | 1.000000 | 1.000000 | 0.0% | YES |
| AUC 随机标签零分布均值（理论 0.5） | 0.489515 | 0.500000 | 2.1% | YES |
| Brier 完美概率（理论 0） | 0.000000 | 0.000000 | 0.0% | YES |
| walk-forward 无泄漏（max train_t < min test_t） | True | True | 0.0% | YES |
| 拟合确定性（两次权重差 0） | 0.000000 | 0.000000 | 0.0% | YES |

**逐项回答：全部 <3%，管线数值正确性成立。**

**但必须分清两件事**：管线算得对（上表全 <3%）≠ 判级有判别力。判据本体（表 2）的结论是 C1/C2/C5 未达标；这个 FAIL 是数据给的，不是实现误差给的——负控零分布 0.4895 对 0.5 只差 2.1%，说明管线没有系统性高估。

## 结论与下一步

1. **外部效度不足**：判级对下游落地的 walk-forward AUC = 0.445（CI 含 0.5），Brier 还不如常数基线，当前 S/E 判级**不能**作为「工程质量预测器」使用。
2. **判级有横截面信息但被时代噪声淹没**：S1 merge 率 53.6% vs S2 30.7%，静态 AUC 0.61；一旦跨波次外推就翻到 0.5 以下。
3. **评分通胀告警已触发**：最高档 S1 占比 37.0% > 30%，而 merge 率仅 39.2% < 50%。
4. 下一步（按性价比排序）：①按「仓×波次」加固定效应重算条件 AUC；②把 CI 红/绿按仓级与工件级拆开（区分仓级坏 main 与单工件缺陷）；③对失败任务建评价记录，补上最硬的正负例；④把本管线接进周期巡检，每波落一份 JSON 看 AUC 与 Brier 的漂移。
