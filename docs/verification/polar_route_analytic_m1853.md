## ① 案例介绍（物理背景 / 几何 / 参数）

冰区航行域的核心决策工具是**最小代价航线规划**：`backend/services/polar/route.py::RoutePlanner`
在冰情网格上做带时间惩罚（Lagrangian `lam` [kg/h]）的 A\* 搜索，输出航线、分段航速、油耗、
航时与推进能耗，服务在线端点 `POST /api/v1/ice-navigation/route`。它是平台冰区域的"门面能力"，
但**此前全仓无任何针对搜索本身**的判决文档——已往冰区验证只覆盖平整冰阻力、碎冰航道、
护航间距、极值冰载荷与冰级优化（`docs/verification/ice_domain_verification_v1.md` 等）。

本单的判据**不引入任何"记忆中的文献表值"**，全部为解析式/自洽基准：精确 Dijkstra 最优性、
启发式可采纳性、逐段记账闭合、无冰时弦线绕行比、冰厚单调性、期限区间与失效诚实性、功率不可行冰区的可航性诚实性。

算例船（平台内置预设，几何先验已由 `validate_geometry` 校验）：

| 参数 | 值 | 参数 | 值 |
|---|---|---|---|
| 船型 | Handysize bulk carrier（1A） | L × B × T | 180.0 × 28.4 × 10.5 m |
| Cb | 0.83 | 设计航速 | 14.0 kn |
| 主机功率 | 7500 kW | SFOC | 178 g/kWh |
| 总推进效率 η | 0.68 | 冰级限制厚度 h_max | 1.0 m |

网格：21 × 13，dx = 4.0 km，stride = 1；
主算例：均匀冰厚 0.9 m / 冰强度 1.2 MPa / 流速 0.25 m/s / 风速 4.0 m/s；
起终点 (8,16) km → (72,32) km。`V_MIN_MS = 0.6 m/s`。

## ② 怎么做的（方法 / 流程 / 关键设置 / 工具链）

1. **独立最优性基准**：在本工具内实现纯 Dijkstra（相同的 `edge_option` 边代价、相同的邻接），
   与 A\* 的 Lagrangian 总代价 `fuel + lam·time` 逐位比对（判据 R1）；边代价与航向相关
   （流/风只在出发节点取值），因此反向 Dijkstra 用 `edge_option(b, a)` 求"到终点的精确剩余代价"，
   用于判据 R2 的**可采纳性**检验。
2. **记账基准**：逐段用规划器自身的正典函数 `segment_fuel()`（含风速沿航迹分量）独立重算油耗/
   航时/距离/推进能耗，与 `_search` 的汇总比对（R3/R4）。这是"同一物理量的两条独立代码路径"对照，
   不涉及外部数据。
3. **解析几何基准**：无冰、无流、无风时最小油耗航线应与起终点弦线重合，判据取绕行比
   `route_km / chord_km ≤ 1.10`（8 邻域网格的离散化下限约为 1 + O(1/N)）。
4. **单调性/边界**：冰厚 0.2→0.8 m 扫描，油耗/公里须严格递增、节点可持续航速上限须单调下降（R6）。
5. **期限语义**：`deadline_h` 取最慢（lam=0）与最快（lam=1e7）之间时，计划须落在
   `[fast, deadline]` 且 `deadline_binding=True`（R7）；不可能期限须抛 `ValueError` 而非伪造计划（R8）。
6. **可航性诚实性**：构造"冰厚足以让 `R(v_min)·v_min/η > P_avail`"的屏障列（h = 0.85 m，
   冰强度 8.0 MPa，仍低于 h_max），检查规划器是否把这类格点当节点、
   是否让航线穿过它（R9）。
7. **航速上限**：每条航段的采用航速须 ≤ min(设计航速, 该节点可持续航速)（R10）。

工具链：纯 numpy + 仓库内物理内核（`holtrop_open_water_resistance` / `ice_components` /
`wind_resistance`），单次全量运行约数秒，**未起任何重算力进程**（本机 load15 ≈ 122 ≥ 100，按容量纪律只做轻量验证）。

### 本单发现并修复的两个缺陷（修复前实测，同套件）

1. **推进能耗用错阻力列（R4）**：`_search` 汇总能耗时用 `r_table[a, 0]`——**最低速档**的阻力——
   乘上实际采用航速，且漏掉风阻项。修复前：报告 94845.464 MJ vs 逐段正典重算 94880.134 MJ
   （相对误差 3.65e-4）；修复后相对误差 0.000e+00。修复方式见 `_leg_resistance()`。
2. **功率不可行冰区被当作可航（R9）**：`__init__` 只按 `h ≤ h_max` 过滤格点，
   而 `max_sustainable_speed_ms()` 对"连 V_MIN_MS 都维持不住"的冰返回 0.0 时，
   `edge_option()` 会静默回落到 V_MIN_MS 继续算油耗——即**穿越船舶根本开不动的冰**。
   修复前：13 个零功率格点被收为节点，航线确实穿过屏障列（节点 94，x = 40 km）；
   修复后：零功率格点一律不收为节点，屏障全高时诚实抛"no navigable route"。
3. **启发式非可采纳（R2）**：原 per-metre 下界只看"静水+冰"的每米代价，**未计入顺流（地速↑、时间↓）
   与顺风（所需推力↓）**，实测 h 高估剩余代价 1931.46 kg（h = 6574.14 kg vs 精确剩余 4642.68 kg，
   高估 42%），A\* 因此在一般算例下可能返回次优航线。修复后下界按"全场最优顺流/顺风"构造，
   最坏 h−剩余 = 0.000e+00 kg。R1 的逐位相等在本算例修复前后都成立，
   说明**本算例**未触发出次优，但判据本身在修复前是红的。

## ⑤ 注意点（踩过的坑 / 局限 / 适用范围）

- **可采纳性只能靠独立 Dijkstra 反证**：自证"看起来合理"的下界会漏掉顺流/顺风项（本单即如此）。
  任何针对该规划器的新启发式都必须过 R2。
- **边代价只取出发节点**：`edge_option` 的流/风只在 `a` 点取值，故图是有向非对称图；
  反向 Dijkstra 必须用 `edge_option(b, a)`，用对称图会得到错误的"剩余代价"。
- **R5 是离散化意义上的解析基准**：8 邻域网格上"直线"只能以阶梯逼近，实测 1.0706；
  阈值 1.10 是网格分辨率（4 km）下的经验界，不应解读为物理绕行能力。
- **R9 屏障列是全高阻断**：本单用整列屏障，因此有时以 `ValueError`（诚实失败）而非"绕行"通过；
  绕行分支由 `tests/test_polar_route_anchor_m1853.py` 的局部屏障场景覆盖。
- **算例船单一**：只判了 handysize_bulker；其余 4 型预设（含 icebreaker_escort）在 h ≤ h_max 内
  未找到功率不可行冰厚（R9 对它们无定义域），其最优性/记账判据未单独跑。
- 本单**未**评估物理内核本身（Holtrop 静水阻力、Lindqvist/Riska 冰阻力）的绝对精度——那属阻力域/冰区阻力的已往判据。
